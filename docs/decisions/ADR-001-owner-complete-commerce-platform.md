# ADR-001：完整 Owner 自用跨境电商平台是唯一开发路径

## Status

Accepted

## Date

2026-07-12

## Context

凌镜已经积累市场研究、商品、货源、Listing、订单、库存、履约、售后、结算、利润、Agent 与平台内核等大量工程能力。此前方向在两个极端之间摇摆：一端是一次建设大而错误的抽象平台，另一端是把单一“小闭环”或“行动卡”误当成产品终点。

Owner 明确决定：完整跨境电商平台是目标。AI 辅助开发显著降低完整实现、测试和边界处理的工程成本，不能因为只有一个 Owner 就主动放弃平台完整性；但完整性只适用于正确领域模型，不能把交易状态链、对象关联或利润终局误称为经营反馈闭环。

外部标杆调研也显示，成熟系统通常将交易事实、经营决策、实验评估和平台执行分开。完整平台应连接这些能力，但不能用一个巨大 `experiment` 对象取代正确边界。

## Decision

凌镜唯一开发路径是：

> 建设一个只供 Owner 本人使用的完整 AI 跨境电商经营平台，使 Owner 能在同一系统中研究市场、形成商品机会、管理货源与商品、受控上架、经营订单与库存、完成履约和售后、核对结算与最终利润，并让真实经营结果形成下一次可执行经营决定。

平台由四个协作部分组成：

1. **经营事实系统**：市场、商品、供应商、Listing、订单、库存、履约、售后、结算、利润和现金的真实对象、来源、状态及对账。
2. **经营决策系统**：经营问题、目标、动作变量、批准、外部执行凭证、观测、偏差、决定和下一动作；只有下一动作再次进入市场才可称反馈循环。
3. **Owner AI 协作层**：小Q作为唯一 Owner Agent，通过登记 Capability 研究、解释、提出动作和协调工作，不绕过 Owner、RBAC、审批、审计和领域规则。
4. **平台内核**：身份、权限、审批、审计、幂等、事件、命令、调度、工具桥、可观测性、备份、恢复和部署，为全部经营能力提供统一安全底座。

完整平台是目的地，开发按可独立验收的完整纵向单元推进。每个纵向单元必须完成必要领域模型、API、Owner 体验、权限、审批、审计、错误处理、自动测试、运行验证和文档；“先做一湖”不是缩小最终平台范围。

## Sole Development Path

依赖顺序如下，现有成熟能力优先复用，不因顺序重复建设：

1. **平台真相与领域合同**：统一事实等级、对象身份、来源、Owner 边界及事实系统/决策系统边界；现有 `experiment` 仅作为待迁移的经营事实案卷。
2. **市场与机会**：候选市场、消费者问题、竞争、获客、履约、合规、收款、反证、Owner 决定和商品机会。
3. **商品、货源与渠道准备**：私人收藏、供应商、样品、成本、合规、图片与内容、SKU、Listing 草稿、Owner 审批和受控发布。
4. **交易经营**：渠道订单、库存、采购/补货、履约、物流、售后、退款、争议和异常处理。
5. **经营财务**：平台结算、费用、税费、广告、汇率、订单利润、现金回收和可复算对账。
6. **经营决策与反馈**：将具体经营问题变成受控行动，保存实际执行与暴露，比较目标和结果，形成并再次执行下一动作；随机或准实验仅在条件满足时启用。
7. **小Q统一经营入口**：在上述领域能力真实存在后逐项登记 Capability，使 Owner 能通过一个 Agent 查看、研究、决定和批准，但不让模型替代确定性事实与高风险控制。
8. **生产经营保障**：完成正式环境的安全、监控、告警、备份恢复、迁移、失败对账、平台契约验证和操作手册，使平台可长期由 Owner 与 AI 共同经营。

各单元不是互相隔离的阶段版本；涉及同一真实纵向流程时，应把跨层依赖一起完成。未经真实市场选择，不预设国家、平台、类目、商品或固定数量。

## Completeness Rule

“做完整”指把当前选定纵向单元的正常路径、失败路径、边界、测试、安全和运行验收全部做完，不以 90% 快捷实现长期搁置缺口。它不授权：

- 恢复外部 SaaS、多租户、订阅、计费、公共 API 或外部 onboarding；
- 把更多 Agent、MoA、自治等级或展示性仪表盘当作平台完整性；
- 未经市场与渠道决定扩张连接器；
- 把模块存在、测试通过或页面可见写成真实经营结果；
- 沿用错误 `experiment` 模型继续扩建。

## Alternatives Considered

### 只做单一行动卡或小工具

可用于验证局部交互，但被拒绝为最终开发方向。它可以成为完整平台中的一个纵向单元，不能成为平台上限。

### 继续沿用经营实验闭环

拒绝。交易终局和对象关联不构成反馈或因果；现有能力只能按经营事实案卷保留并迁移。

### 一次性建设所有模块

拒绝作为推进方式。完整平台是目的地，但缺少依赖顺序和逐单元验收会让错误扩散到全平台。

### 对外 SaaS 平台

冻结。当前唯一用户是 Owner；完整指 Owner 自用经营能力完整，不指客户、租户或商业化功能完整。

## Consequences

- 任何计划、TODO、PR 和验收必须能映射到上述唯一开发路径中的一个纵向单元；无法映射的工作默认不进入当前队列。
- 不再以“小工具足够”否决平台能力，也不以“完整平台”为由加入无关功能。
- 现有模块需按正确领域边界分类为复用、改造、迁移、冻结或删除，不能因历史投入自动保留。
- 真实经营价值仍需外部事实验证；工程完整与经营结果必须继续分级报告。
- 方向变更只能由 Owner 形成新的 Accepted 决策并明确取代本 ADR。
