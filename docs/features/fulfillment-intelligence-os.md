# 功能需求：履约智能中枢 Fulfillment Intelligence OS

> 添加时间：2026-07-03
> 提出人：Owner
> 优先级：P1

## 一句话说明

把物流从后台配置和报价工具，升级为 AIOS 的履约智能中枢：系统能够在选品、定价、订单发货、物流异常、账单审计和复盘中持续判断“怎么发最不亏、最稳、可追踪、可审计”。

## 背景

跨境电商的物流不是单一功能，而是贯穿经营链路的成本和风险变量。它直接影响：

- 商品是否适合销售到某个国家。
- 商品最低不亏售价。
- 订单利润是否被运费吞掉。
- 发货渠道是否满足时效和平台考核。
- 物流商账单是否存在多收、错收或规则偏差。
- 丢件、延误、退件是否造成售后和差评。

当前系统已有 `shipping` 和 `logistics` 两类能力：

- `shipping` 更接近业务事实层，管理物流商、渠道、区域、报价规则、账单和订单运费快照。
- `logistics` 更接近计算内核，提供费率计算、路线推荐、合单议价和 A10 相关统计。

后续不应简单把二者合并，也不应先接真实物流 API。更合理的方向是明确分层：`shipping` 承载业务主数据和订单事实，`logistics` 承载可复用的计算与推荐引擎，A10 Agent 负责建议、审计和复盘。

## 最终目标

履约智能中枢最终要让 Owner 和 AgentOS 能回答这些问题：

```text
这个商品适合卖到哪些国家？
这笔订单应该怎么发才不亏、稳定、可控？
哪个物流渠道正在拖累利润？
物流商账单有没有多收？
如果某条渠道涨价，哪些商品和订单会受影响？
A10 建议了什么，是否被采纳，最终结果如何？
```

系统能力应覆盖完整闭环：

```text
商品物流资料
→ 选品利润判断
→ 定价底线
→ 订单发货决策
→ 运费快照
→ 轨迹与异常
→ 物流商账单
→ 承运商绩效
→ A10 复盘建议
→ 下一轮选品、定价、发货策略
```

## 真实业务路径

### 1. 选品与定价前

商品进入备选池后，系统读取或提示补齐包装重量、包装尺寸、货品类型，并对不同目的国进行物流成本模拟。

系统应识别：

- 轻小件。
- 抛货。
- 高运费风险商品。
- 敏感品、带电、液体等渠道受限商品。
- 不适合销售到某些国家的商品。
- 适合集单、海外仓或特定渠道的商品。

### 2. 订单成交后

订单进入履约阶段后，系统按订单目的国、邮编、SKU 包装、货品类型、利润要求和时效要求生成物流建议。

建议不应只按最低价排序，还应考虑：

- 预计运费。
- 预计时效。
- 订单利润。
- 渠道限制。
- 承运商近期稳定性。
- 目的国近期延误率。
- 平台履约考核风险。
- 客户等级或订单优先级。

### 3. 发货时

运营选择渠道或批准 A10 建议后，系统必须保存不可变的订单运费快照。

快照保存的是当时的履约事实，不允许后续费率变化覆盖历史订单。

### 4. 发货后

系统跟踪物流状态、签收结果、超时、退件、丢件、破损和售后关联。第一阶段可以通过导入或人工录入形成事实，真实物流 API 可后置。

### 5. 账单回来后

物流商账单导入系统后，与订单运费快照进行匹配和对账。

系统识别：

- 实际运费高于预估。
- 重量或体积重异常。
- 偏远费异常。
- 燃油附加费异常。
- 重复收费。
- 未匹配订单。
- 币种或汇率异常。

### 6. 复盘后

实际成本、时效、异常和售后结果反哺承运商绩效，影响下一次报价推荐、选品判断和发货建议。

## AIOS 蓝图分层

### L1 数据感知层

采集和沉淀履约相关事实：

- 商品/SKU 包装数据。
- 订单目的国、邮编、SKU、数量和利润信息。
- 物流商、渠道、区域和货品限制。
- 费率规则和规则版本。
- 运费快照。
- 运单号和轨迹节点。
- 物流商账单。
- 售后、退款、退件、丢件、破损。

### L2 物流知识层

形成可复用的履约知识：

- 国家/区域履约特征。
- 货品类型限制。
- 计费规则。
- 体积重规则。
- 渠道画像。
- 异常模式。
- 承运商历史表现。

### L3 决策引擎层

提供可解释的计算和判断：

- 多渠道报价。
- 路由推荐。
- 利润保护。
- 规则变更影响分析。
- 账单审计。
- 承运商绩效评分。
- 履约风险评分。

### L4 Agent 协作层

A10 不孤立工作，应与其他 Agent 协同：

- A1 选品：判断商品是否适合跨境销售。
- A2 刊登：判断商品应销售到哪些国家和平台。
- A5 库存：判断是否需要换仓、补货或改变备货策略。
- A6 利润：判断运费变化是否导致亏损。
- A7 合规：判断货品类型和渠道限制是否匹配。
- G0/G1：判断物流异常是否影响经营健康。
- Finance：判断账单和结算是否异常。

### L5 审批执行层

高风险动作必须可审批、可审计、可追踪。

需要审批的动作包括：

- 修改订单物流方式。
- 创建生产物流单。
- 获取生产面单。
- 取消或拦截物流单。
- 调整价格。
- 下架商品。
- 修改订单状态。
- 对外部物流商发起生产调用。

A10 可以准备建议和动作草稿，但不能绕过审批直接执行高风险生产动作。

### L6 复盘进化层

每次建议和执行都应形成反馈：

```text
A10 建议
→ 人是否采纳
→ 实际执行动作
→ 实际成本
→ 实际时效
→ 异常和售后
→ 账单偏差
→ 承运商评分更新
→ 下一次推荐变化
```

## 底层基建

### 1. 商品物流数据底座

每个商品/SKU 必须具备可计算运费的基础资料：

- 包装重量。
- 包装长宽高。
- 货品类型。
- SKU 覆盖商品包装数据的规则。
- 物流资料完整性状态。

### 2. 物流商与渠道主数据

系统需要维护可选物流池：

- 物流商。
- 渠道。
- 支持国家、区域、邮编。
- 支持货品类型。
- 预计时效。
- 抛重系数。
- 启用/禁用状态。

### 3. 费率规则引擎

统一所有报价入口的计算来源：

- 首重续重。
- 固定费加每公斤。
- 阶梯价。
- 最低收费。
- 燃油附加费。
- 偏远附加费。
- 体积重和计费重。
- 币种。
- 生效时间、失效时间和规则版本。

### 4. 订单运费快照

订单选择物流渠道后，必须保存不可变快照：

- 订单 ID、SKU ID。
- 目的国、邮编。
- 包装重量、长宽高。
- 实重、体积重、计费重。
- 物流商、渠道。
- 命中的规则版本。
- 基础运费、附加费、燃油费、总运费。
- 币种。
- 报价时间。
- 选择人或触发来源。

### 5. 履约状态底座

发货后需要记录：

- 运单号。
- 承运商。
- 发货时间。
- 当前物流状态。
- 轨迹节点。
- 签收时间。
- 是否超时。
- 是否丢件、退件、破损。
- 关联售后结果。

### 6. 物流账单与对账底座

账单导入后应能匹配订单快照并识别偏差：

- 账单批次。
- 账单行。
- 订单匹配结果。
- 预估运费。
- 实际运费。
- 差异金额。
- 差异比例。
- 异常原因。
- 复核状态。

### 7. 承运商绩效数据底座

长期沉淀每个渠道的真实表现：

- 平均实际运费。
- 平均时效。
- 准时率。
- 超时率。
- 丢件率。
- 退件率。
- 破损率。
- 售后率。
- 账单偏差率。
- 国家和品类维度表现。

### 8. 事件、审批和审计底座

所有重要建议和动作必须回答：

- 为什么触发？
- 使用了哪些数据？
- 推荐了什么？
- 谁批准或拒绝？
- 最终执行了什么？
- 影响了哪些订单、商品和利润？
- 审计记录在哪里？

## 分阶段规划

### 阶段 0：定义履约事实标准

目标：先统一业务口径和数据口径。

产出：

- 订单级履约快照标准。
- 物流费率版本标准。
- 承运商绩效指标标准。
- A10 建议记录标准。
- 高风险动作审批边界。

验收：

- 能完整描述一笔订单从预估到实际的字段。
- 能明确什么叫最优物流：利润优先、时效优先、风险优先或平台考核优先。

### 阶段 1：报价与订单快照夯实

目标：让每笔订单发货前算得准，发货时存得住。

建设内容：

```text
SKU 包装数据
→ 物流商/渠道/规则
→ 统一报价引擎
→ 订单运费快照
→ 利润影响计算
```

验收：

- 同一订单在不同入口算出的运费一致。
- 历史订单能查到当时为什么是这个运费。
- 订单利润能基于运费快照计算。
- 费率变更不影响历史订单。

### 阶段 2：账单对账与异常识别

目标：知道物流商有没有多收，系统预估准不准。

建设内容：

```text
物流商账单导入
→ 匹配订单快照
→ 比较预估 vs 实际
→ 标记异常
→ 形成复核任务
```

验收：

- 能列出本月运费差异最大的订单。
- 能按物流商、渠道、国家统计账单偏差。
- A10 能生成需要人工复核的建议。

### 阶段 3：履约状态与承运商绩效

目标：从只看便宜升级到判断稳定性。

建设内容：

```text
运单号
→ 轨迹节点
→ 签收/超时/丢件/退件
→ 售后关联
→ 承运商绩效评分
```

验收：

- 能看出某个渠道在某国家、某品类是否稳定。
- 发货推荐能结合价格、时效和风险。
- A10 能解释不推荐某渠道的原因。

### 阶段 4：A10 履约智能 Agent

目标：让 A10 从报表助手升级为履约决策助手。

A10 输入：

- 订单。
- SKU 包装。
- 目的国。
- 利润要求。
- 可用渠道。
- 费率版本。
- 历史绩效。
- 账单偏差。
- 售后记录。
- 平台时效要求。

A10 输出：

- 推荐渠道。
- 推荐理由。
- 不推荐渠道。
- 预计成本。
- 预计时效。
- 利润影响。
- 风险等级。
- 是否需要审批。
- 建议动作。

验收：

- 每条建议都有数据依据。
- Owner 能看懂建议并决定批准或拒绝。
- 系统记录建议是否被采纳和后续结果。

### 阶段 5：受控执行与外部物流 API

目标：在审批和审计完整后，再让系统执行真实物流动作。

执行能力：

- 查询实时报价。
- 创建物流单。
- 获取面单。
- 查询轨迹。
- 取消或拦截。
- 拉取账单。
- 向物流商提交申诉。

必须具备：

- dry-run、sandbox、production 模式。
- 幂等键。
- 审批 ID。
- 审计日志。
- 失败重试。
- 回滚说明。
- 凭证管理。

验收：

- Agent 不能绕过审批执行高风险动作。
- 每次真实发货、改渠道、创建面单都有审计记录。
- 外部 API 失败时系统可降级，不影响订单基本处理。

## 一期推荐范围

第一期只做这句话：

> 每笔订单发货前有预估，发货时有快照，账单回来能对账。

一期范围：

- 统一报价入口。
- 补强订单运费快照。
- 费率规则版本化。
- 物流账单导入和对账。
- A10 输出账单异常和渠道异常建议。

一期不做：

- 真实物流商生产 API。
- 自动创建物流单。
- 自动修改订单物流方式。
- 自动调价或下架。
- 复杂装箱优化。

## 风险等级

整体为高风险规划，因为它影响：

- 订单履约。
- 运费和利润。
- 外部物流商调用。
- Agent 建议和未来自动化。
- 审批、审计和操作责任。

实施原则：

- 先只读和建议，再审批执行。
- 先内部快照和对账，再真实 API。
- 先可解释，再自动化。
- 任何生产物流动作都必须经过审批和审计。

## 估算

- 后端工作量：高。需要报价入口统一、快照模型、对账模型、绩效沉淀、A10 输出结构化。
- 前端工作量：中高。需要订单履约视图、对账视图、A10 建议视图和异常处理入口。
- 数据库变更：是。
- 外部服务依赖：阶段 5 之前不强依赖真实物流商 API。

## 依赖

- 商品/SKU 包装数据完整性。
- 订单模块可保存和展示运费快照。
- 物流渠道和费率规则可维护。
- 审批、审计、RBAC 和 Agent Action 合约。
- 账单导入能力。
- A10 建议记录和执行结果回流。

## 验收标准

阶段性验收：

- 所有报价入口使用同一套计费逻辑。
- 订单保存不可变运费快照。
- 费率规则变更不影响历史订单利润。
- 账单导入后能识别预估和实际差异。
- 能按物流商、渠道、国家查看账单偏差。
- 能按渠道查看平均时效、超时率、丢件率和账单偏差率。
- A10 建议包含原因、风险、数据依据和审批要求。
- 高风险生产动作不能绕过审批和审计。

最终验收：

- Owner 可以询问系统“最近物流哪里拖累利润”“哪些商品不适合卖到某国”“这批订单怎么发最稳”“物流商有没有多收”，系统能基于事实数据给出可解释建议。

## 备注

本蓝图是方向性文档，不代表一次性实现范围。后续应拆分为独立实施计划，建议先从”报价统一 + 订单运费快照 + 账单对账”开始。
