# LingMirror 凌镜 — 小范围试运行指南

更新时间：2026-07-01

## 试运行目标

验证 AI Agent 系统在真实业务场景下的稳定性、可用性和安全性。

## 试运行范围

- 参与 Agent：A5 库存助理、A6 利润看护、A7 合规专员、G0 系统健康员
- 只读 + 建议模式，所有高风险操作需 Owner 审批
- 不涉及真实外部平台发布

## 试运行前准备

1. [ ] 后端服务正常运行（`curl http://localhost:8080/api/health` 返回 ok）
2. [ ] 前端页面可访问（`http://localhost:3000`）
3. [ ] 数据库迁移已执行（migrations/）
4. [ ] JWT 密钥已配置

## 试运行流程

### 第一步：登录系统
访问 `/login`，使用管理员账号登录。

### 第二步：查看 Owner 总控台
访问 `/owner`，查看：
- 风险摘要卡片（待审批、低利润、资料不完整、同步异常）
- Agent 上架建议列表
- Agent 活动摘要（正在运行、已完成、失败的 Agent 任务）
- Agent 流程管道健康度

### 第三步：查看 AgentOS 驾驶舱
访问 `/agentos`，查看：
- Agent 列表和状态
- 工作队列（待审批/处理中的统一动作）
- Squads 健康地图
- 最近 Agent 活动时间线

### 第四步：审批 Agent 建议
- 访问 `/approval` 或通过 Owner 总控台的建议列表
- 对于"推荐上架"的建议，点击"批准"创建审批请求
- 对于有风险的建议，点击"拒绝"并注明原因

### 第五步：查看上架任务
- 访问 `/listing-tasks` 查看已批准的刊登任务
- 访问 `/listing-tasks/[id]` 查看任务详情和执行状态

### 第六步：检查运行状态
- 访问 `/agentos` 检查是否有失败的 Agent 运行（`failures` 区域）
- 访问 `/operation-logs` 查看操作审计日志
- 检查 AgentOS 驾驶舱中的 SLA 超期和工作队列长度

## 试运行监控要点

| 关注点 | 查看位置 | 正常指标 |
|--------|----------|----------|
| Agent 运行失败 | `/agentos/failures` 或 AgentOS 驾驶舱 | 无持续失败 |
| 审批积压 | Owner 总控台 → 审批数 | 建议 < 5 个待审批 |
| 工作队列 | AgentOS 驾驶舱 → 工作队列 | 建议 < 20 个待处理 |
| 失败 Agent | AgentOS 驾驶舱 → 失败检查 | 无 "critical" 状态 Squad |

## 常见问题

**Q: Agent 运行失败了怎么办？**
A: 访问 `/agentos/failures` 查看失败原因。常见原因包括：
- LLM 调用超时（检查网络连接和 API 密钥）
- Agent 输入数据不足（补充业务数据）
- 策略规则阻止（检查 action policy 配置）

**Q: 审批请求没有收到怎么办？**
A: 访问 `/approval` 查看所有待审批请求。如果仍然没有，检查 Agent 是否正常运行。

**Q: 如何确认系统运行正常？**
A: 使用 Owner 总控台查看 Agent 活动摘要和流程管道健康度。如果有红色 "critical" 标记，需检查具体 Agent 状态。

## 风险说明

- 当前系统运行在**模拟/沙箱模式**，所有平台同步为 mock 数据
- 高风险动作（改价、改库存、发布商品）已被系统阻断，必须通过审批
- 单个 Agent 失败不会影响其他 Agent 运行
- 所有 Agent 操作均有审计日志可追溯
