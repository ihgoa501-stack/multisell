## 1. 执行摘要

### 1.1 项目背景

基于对跨境电商全岗位体系（8大群组、52个细分角色）、真实业务场景（12个角色每日小时级操作流、5条跨部门协作链）、以及AI Agent设计方案的全面交叉分析，形成本综合方案。

### 1.2 核心结论

| 维度 | 结论 |
|------|------|
| **自动化潜力** | 约70%的日常运营决策有明确规则可循，可被Agent替代或增强 |
| **最高ROI切入点** | 广告调价 > 多语言客服 > 库存预警 > 利润监控（Phase 1四箭齐发） |
| **最大差异化机会** | 利润监控Agent——市场几乎空白 |
| **最大空白** | 仓储/海关自动化在岗位分析中排名Tier 1，但现有Agent设计未覆盖 |
| **最关键前置条件** | 统一数据层——数据孤岛是所有文档一致认定的#1痛点 |

## 6. P0 Agent 详细设计

> P0定义：Phase 1 (0-3月) 优先实施，满足「ROI最高 + 技术可行 + 业务紧迫」三条标准。
> 含P0核心Agent (A3/A4/A5) 和P0空白填补Agent (G1/G3)。

### 6.1 Agent 3 — 广告智能调价

**定位**：L1完全替代日常出价调整 + L2人机协作结构优化

#### 输入数据源

| 数据 | 来源 | 频率 |
|------|------|:--:|
| 广告活动表现（曝光/点击/转化/花费/ACoS） | Amazon Ads API | 每小时 |
| Search Term Report (STR) | Amazon Ads API → SP-API Reports | 每日 |
| 产品库存状态 | ERP / SP-API FBA Inventory | 实时 |
| 竞品价格变动 | Keepa API | 每小时 |
| 历史转化率曲线 | 内部数据库 | 持续 |

#### 核心决策逻辑

```
输入: 广告活动当前ACoS, 目标ACoS阈值, 库存状态, 竞品价格变动

决策树:
├── ACoS < 目标阈值下限 (成熟品<10%, 新品<30%)
│   ├── 库存充足, 竞品无降价 → 温和提价+10%
│   ├── 库存充足, 竞品降价>5% → 保持出价, 标记竞品响应
│   └── 库存紧张 (<7天) → 降低出价-20%, 减缓销售速度
│
├── ACoS 在目标区间内 → 保持, 微调±5%
│
├── ACoS > 目标阈值上限 (成熟品>20%, 新品>50%)
│   ├── 转化率正常 → 降低出价-15%
│   ├── 转化率下降>20% → 检查Listing是否被抑制/差评
│   └── 连续3天超标 → 暂停广告活动, 推送人工审核
│
└── 特殊情况:
    ├── 库存接近断货 (<3天) → 立即暂停所有广告
    ├── 竞品大幅降价>15% → 推送竞品响应策略建议
    └── 大促期间 → 切换至大促模式(目标ACoS放宽+50%)
```

#### ACoS阈值分级

| 产品阶段 | ACoS目标区间 | 调价策略 |
|---------|:----------:|---------|
| 新品推广期 (0-30天) | 30-50% | 激进获评，容忍高ACoS |
| 成长期 (30-90天) | 15-25% | 逐步收紧，优化关键词 |
| 成熟期 (90天+) | 10-20% | 稳定盈利，防守竞品 |
| 清仓期 | 10-15% | 快速去库存，避免长期仓储费 |

#### 调价频率

- 日常：每4-5小时一轮（对应欧美工作时间窗口）
- 大促期间：每小时一轮
- 每日最多调整轮数：6轮（防止过度调整）

#### 输出格式

```json
{
  "timestamp": "2026-06-16T14:00:00Z",
  "campaign_id": "SP-A1B2C3",
  "decisions": [
    {
      "action": "adjust_bid",
      "keyword": "B0XXXXX",
      "old_bid": 0.45,
      "new_bid": 0.38,
      "reason": "ACoS 35% exceeds mature threshold 20%",
      "confidence": 0.92
    }
  ],
  "paused_campaigns": [],
  "alerts": [
    {
      "level": "warning",
      "message": "Stock for ASIN B0YYYYY below 3 days, consider pausing ads",
      "action_required": true
    }
  ]
}
```

### 6.2 Agent 4 — 多语言智能客服

**定位**：L1自动回复60%+重复问询，L2辅助客服处理复杂投诉

#### 支持语言与渠道

| 语言 | 渠道 | 自动化率目标 |
|------|------|:--------:|
| 英语 | Amazon Buyer-Seller Messaging, Shopify Chat, Email | 70%+ |
| 德语 | Amazon DE, Email | 65%+ |
| 法语 | Amazon FR, Email | 60%+ |
| 西班牙语 | Amazon ES, Email | 60%+ |
| 日语 | Amazon JP, Email | 55%+ |
| 中文 | 内部协作 (运营↔采购↔物流) | N/A |

#### 意图分类与路由

```
用户消息 → NLP意图识别 → 置信度评分:
├── 高置信度(≥90%) + FAQ匹配 → L1自动回复
├── 中置信度(70-90%) → L2 生成建议草稿 → 推送人工确认
├── 低置信度(<70%) → 升级人工 + 标记紧急度
└── 高风险关键词(trademark, lawsuit, refund, A-to-Z) → 强制人工
```

#### 60%FAQ覆盖矩阵

| 问询类别 | 占比 | 处理方式 | 置信度要求 |
|---------|:--:|---------|:--------:|
| 物流查询 (Where is my order?) | 25% | 调用17TRACK API + 模板回复 | ≥90% |
| 产品使用问题 | 15% | 知识库RAG检索 + 生成回复 | ≥85% |
| 退换货流程 | 10% | 规则引擎 + 模板 | ≥95% |
| 尺码/规格确认 | 5% | 知识库检索 | ≥90% |
| 促销/折扣咨询 | 5% | 规则引擎 | ≥95% |
| 其他重复问询 | 5% | 综合RAG | ≥85% |

#### SLA时区覆盖

```
北京时间:
  09:00-18:00 → 人工客服为主, Agent辅助
  18:00-09:00 → Agent全权处理 (覆盖美国白天)

SLA目标:
  美国日间(EST 9AM-9PM): 首次响应 < 5分钟
  其他时段: 首次响应 < 30分钟
  直播场景: < 30秒 (影响CVR 12-18%)
```

#### 异常升级规则

| 触发条件 | 升级路径 | 响应时间 |
|---------|---------|:------:|
| 客户情绪愤怒 (情感分析 negative + 愤怒关键词) | → 客服主管 | < 15分钟 |
| A-to-Z Claim 或 Chargeback | → 纠纷处理专员 + 运营主管 | < 30分钟 |
| 法律/合规相关措辞 | → 法务 + 品牌经理 | < 1小时 |
| 3轮对话未解决 | → 二线客服 | < 30分钟 |
| Agent置信度<70%连续3次 | → 自动升级人工 | 即时 |

### 6.3 Agent 5 — 库存智能预警

**定位**：L1自动监控+L1自动生成补货建议，关键决策L2人工确认

#### 三级预警体系

| 预警级别 | 触发条件 (可售天数) | 响应动作 |
|:----:|------|---------|
| 🔴 **红色预警** | ≤7天 (快消品≤3天) | 暂停广告 → 通知采购紧急补货 → 通知运营考虑提价 → 推送管理层 |
| 🟡 **黄色预警** | 7-14天 (快消品3-7天) | 生成补货建议 → 推送采购确认 → 广告酌情降投 |
| 🟢 **绿色正常** | >14天 | 日常监控，无需干预 |

#### 补货数量公式

```
补货建议量 =
    安全库存覆盖天数 × 日均销量预测
  - 当前FBA可售库存
  - 在途库存
  + 缓冲量(max(7天销量, 最低MOQ))

其中:
  日均销量预测 = Holt-Winters 时序模型 (考虑季节因子 + 趋势)
  安全库存覆盖天数 = 采购提前期 × 1.5 (含缓冲)
  最低MOQ = 供应商最低起订量
```

#### 物流决策树

```
补货需求触发 → 选择物流方式:
├── 红色预警 (紧急)
│   ├── 货值高 → 空运/国际快递 (DHL/UPS)
│   ├── 货值低 → 空运 + 海运快船并行
│   └── FBA有库容 → 直接发FBA
│
├── 黄色预警 (常规)
│   ├── 海运价格可接受 → 海运 (美西15-20天/美东25-35天)
│   ├── 旺季(10-12月) → 提前预留2周缓冲
│   └── 考虑铁路/快船 (中欧班列/美森快船)
│
└── 绿色正常
    └── 常规海运，按采购计划节奏
```

#### 异常检测

- FBA预留库存突增 (可能在转运但显示不可售) → 触发调查
- 销量突降 (>30% vs 7日均值) → 检查Listing/BuyBox/竞品降价
- 销量突增 (>50% vs 7日均值) → 检查是否被竞品断货承接流量，调整补货量

### 6.4 Agent 6 — 多平台利润监控

**定位**：L1自动数据归集+利润计算，L3异常归因分析

#### 收入归集矩阵

| 数据项 | 亚马逊 | 独立站(Shopify) | TikTok Shop | 来源 |
|--------|:-----:|:------------:|:----------:|------|
| 销售额 | ✅ SP-API Finances | ✅ Shopify API | ✅ TikTok API | API |
| 退款/退货 | ✅ | ✅ | ✅ | API |
| 平台佣金 | ✅(15%) | ✅(0-2.9%) | ✅(5-8%) | 计算 |
| FBA费用 | ✅ | N/A | N/A | SP-API |
| 广告花费 | ✅ Ads API | ✅ 各渠道API | ✅ | API |
| 头程物流费 | ERP | ERP | ERP | ERP |
| VAT/关税 | 手动→API | 手动 | 手动 | ERP |
| 仓储费 | ✅ SP-API | N/A | N/A | API |
| 汇率损益 | ✅ 汇率API | ✅ 汇率API | ✅ 汇率API | ERP |

#### 利润计算公式

```
单品净利润 =
    销售额 (各站点币种 → 人民币, 按实时汇率)
  - 退款金额
  - 平台佣金
  - FBA费用 (拣货/包装/重量处理/存储)
  - 广告花费 (分摊至SKU)
  - 头程物流费 (分摊)
  - 产品成本 (采购价)
  - VAT/关税
  - 其他费用 (退货处理费/长期仓储费/移除费等)

日/周/月汇总:
  总净利润 = Σ单品净利润
  净利润率 = 总净利润 / 总销售额
  ROAS = 广告带来的销售额 / 广告花费
  综合ACoS = 总广告花费 / 总销售额
```

#### 异常检测规则

| 异常类型 | 检测规则 | 自动动作 |
|---------|---------|---------|
| 利润率骤降 | 单品净利率单日下降>10pp | 排查广告花费/FBA费/退款率 |
| 费用异常 | FBA费用同比上升>20% | 检查产品尺寸重量分类是否变更 |
| 退款率异常 | 退款率>行业均值2倍 | 推送质检+客服联合审查 |
| 汇率冲击 | 汇率单日波动>2% | 推送预警，建议调整定价 |
| 折扣叠加异常 | 多促销同时生效致毛利为负 | 立即推送运营+财务 |

### 6.6 G3 — 折扣风控 Agent（空白填补）

**设计依据**：panorama §7.1标记折扣叠加为"最高频运营事故"，可致零元订单（Coupon + Promotion + Member Discount叠加后售价<$0）。

**定位**：L1全自动防错 + 实时阻断

#### 检测逻辑

```
每次促销设置变更 → 扫描所有生效折扣:
├── 同一ASIN上生效折扣数 ≥ 2 → 模拟叠加后价格
│   ├── 折后价 < 成本价 → 🚫 阻断 + 推送运营确认
│   ├── 折后价 < 成本价×1.1 → ⚠️ 预警（利润率不足10%）
│   └── 折后价 ≥ 成本价×1.1 → ✅ 放行
│
└── 跨平台折扣冲突检测 (如亚马逊和独立站同时大幅降价)
    └── 价差>30% → ⚠️ 可能触发平台"最低价"条款
```

#### 阻断规则

| 场景 | 动作 |
|------|------|
| 叠加后售价≤$0 | 立即阻断，禁止设置 |
| 叠加后售价<采购成本 | 阻断，推送运营+财务审批 |
| 叠加后毛利<5% | 阻断，提示利润率过低 |
| 大促期间Prime Day Deal + Coupon叠加 | ⚠️ 特殊放行（需运营确认） |

### 8.1 断货应急链（A5→A3→A4 串联）

```
  → 通知 G1 驾驶舱: 标记红色预警SKU
```

### 8.2 质量异常追溯链（A4→A6→A5→A2 串联）

```
A4 多语言客服: 检测到某SKU退货/差评激增 (>2倍周均值)
  → 触发 A6 利润监控: 核算该SKU退货损失
  → 触发 A5 库存预警: 质检在途/在库库存
  → 通知 A2 Listing: 检查评论是否含有"缺陷/损坏"关键词
  → 推送运营+质检: "SKU X 质量问题预警，建议暂停销售+质检"
```

### 8.3 大促备战链（全Agent协同，A5核心）

```
T-30天:
  A6 利润监控 → 计算历史大促ROI → 辅助预算决策
  A5 库存预警 → 大促备货量模拟 → 推荐安全库存
  G3 折扣风控 → 大促折扣策略模拟 → 避免叠加事故

T-7天:
  A1 选品扫描 → 竞品大促策略扫描 → 定价调整建议
  A2 Listing优化 → 大促A+页面/A+内容生成 → 转化率提升
  A4 多语言客服 → 加载大促FAQ话术 → 准备流量峰值

T-Day:
  A3 广告调价 → 切换大促模式(放宽ACoS 50%) → 每小时调价
  A5 库存预警 → 实时库存监控 → 每30分钟刷新
  A4 多语言客服 → 全量FAQ自动回复 → 仅复杂问题升级

T+3天:
  A6 利润监控 → 大促ROI终算 → 总结经验
  A4 多语言客服 → 售后集中处理 → 退货/差评预案
```

### 8.4 竞品响应链（A1→A2→A3→A6 串联）

```
A1 选品扫描: 检测到竞品降价>15% 或推出高度相似新品
  → 触发 A2 Listing: 分析竞品Listing差异 → 生成优化建议
  → 触发 A3 广告调价: 竞品防御策略 → 调整出价/增加防守关键词
  → 触发 A6 利润监控: 模拟降价后利润影响
  → 推送运营决策: "竞品X降价15%，建议: ①跟进降价(利润-8%) ②强化差异化 ③增加广告投入"
```

### 10.2 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Workflow Engine | LangGraph (Agent编排) + n8n (定时任务) | LangGraph擅长条件分支和Agent间状态管理；n8n擅长定时和第三方集成 |
| LLM选型 | GPT-4o (主力) + Claude (合规/法律) | GPT-4o性价比高；Claude在法律文本准确性上更优 |
| 预测模型 | Prophet (趋势) + LSTM (销量预测) | Prophet快速可解释；LSTM处理多变量非线性 |
| 数据仓库 | PostgreSQL (事务) + ClickHouse (分析) | PG处理Agent状态和工单；ClickHouse处理海量广告/销售日志 |
| 消息推送 | 企业微信机器人 | 已在T+0/T+30min/T+2h的超时提醒体系中验证成熟 |
| 人工审核 | 企微交互卡片 + n8n Webhook回调 | 已在1688审核流程中验证的四步模式 |
