# 跨境实物商品完整经营闭环与系统边界

> 日期：2026-07-11
> 范围：平台无关；适用于市场平台、独立站、批发、分销等实物商品渠道的共同经营骨架。
> 用途：先定义业务闭环与系统责任，不是开发计划，也不授权采购、发布、广告或资金动作。

## 一、核心结论

跨境实物商品经营不是“选品 → 上架 → 出单”，而是一个从不确定机会出发，经过商品、供应、交易和履约，最终完成客户结果、账务利润、现金回收和组织学习的循环：

```text
市场空间扫描
→ 需求问题与反证
→ 可服务细分机会
→ 产品概念与可测需求规格
→ 供应/合规/履约/财务联合可行性
→ Owner 批准最小真实实验
→ 供应商验证、打样与设计冻结
→ 合规/IP/合同/生产/验货
→ 进出口、物流、到货隔离与库存放行
→ 渠道选择、定价与可售准备
→ 获客、订单、支付与库存承诺
→ 履约、交付、售后、退货与争议
→ 结算对账、税费和全部成本归集
→ 最终净利润确认
→ 现金真正回收
→ 补货/优化/换渠道/停售/退出
→ 结论和证据返回下一轮机会发现
```

完整闭环必须同时闭合：

1. **客户结果链**：真实买家付款、收到商品，售后责任闭合；
2. **商品责任链**：规格、供应、质量、合规、追溯、质保和召回可控；
3. **账务利润链**：收入、退货、税费、库存和全部成本已最终归集；
4. **现金链**：应收、冻结款、退款准备金和供应商账期结束，现金可再次使用；
5. **学习链**：继续或退出的原因被记录，并改变下一轮决策。

## 二、节点不等于系统

流程节点描述“事情走到哪里”；业务系统描述“谁围绕什么对象，对什么结果负责”。因此不能把每个节点做成独立系统。

建议当前采用：**一个凌镜应用、一个统一事实源、六个业务能力模块、一条端到端状态链、一个共用经营控制层**。

| 业务能力模块 | 核心对象 | 负责的完整结果 | 主要节点 |
|---|---|---|---|
| 1. 机会与需求 | 机会案件、证据、需求假设、细分机会 | 形成值得进入真实实验的可证伪机会 | 市场扫描、需求证据、反证、细分与组合排序 |
| 2. 商品定义 | 产品概念、需求规格、SKU/版本、验证计划 | 把客户问题翻译成可采购、可测试、可追溯的商品要求 | 概念比较、规格、样品验证、设计冻结、实验批准 |
| 3. 供应与合规 | 供应商、报价、样品、合同、批次、合规档案 | 稳定、合法、可追溯地取得符合冻结规格的货物 | 供应商验证、打样、IP/合规、采购、生产、验货、召回准备 |
| 4. 渠道与交易 | 渠道方案、报价、客户、订单、支付 | 在有资格的渠道获得非关联客户的真实付款 | 渠道选择、定价、可售准备、获客、订单、支付、反欺诈 |
| 5. 履约与客户结果 | 库存、包裹、签收、售后、退货、争议、质保 | 把正确商品交付给客户并闭合后续责任 | 入库放行、库存承诺、运输交付、退货退款、拒付、质保、召回 |
| 6. 财务与经营决策 | 现金、结算、成本、税费、利润、经营组合 | 确认最终净利润和现金回收，并作出继续或退出决定 | 对账、成本归集、现金周期、补货、优化、停售、清货与复盘 |

模块边界不是部署边界。目前不需要六套软件、六个数据库或六组微服务。只有当某个模块出现独立团队、独立规模、独立运行或独立商业价值时，才重新评估拆分。

## 三、统一主对象与关联对象

全流程不能只靠 SKU 串联，因为 SKU 出现之前已经有大量机会证据，SKU 结束以后仍有售后和财务责任。

建议顶层使用一个统一的 **经营实验案件**：

```text
experiment_case
  ├─ opportunity_case / evidence / counter_evidence
  ├─ product_concept / requirement_spec / sku_version
  ├─ supplier / sample / purchase_order / production_batch
  ├─ compliance_case / shipment / inventory_lot
  ├─ channel_offer / customer / order / payment
  ├─ delivery / return / dispute / warranty / recall
  └─ settlement / cost_entry / tax / cash_movement / final_decision
```

所有关键记录必须能回溯到同一个实验案件；同时保留自身真实业务编号，不能用一个万能 ID 替代订单号、批次号、结算号等专业主键。

## 四、贯穿全部模块的经营控制层

这些能力不能被某一个业务模块独占，也不能等到末端才补：

- **证据与时效**：来源、采集时间、原始内容、事实/估计/未知/推断、过期规则；
- **反证与冲突**：强制记录最强反证，冲突不得静默覆盖；
- **审批与权限**：采购、资金、广告、发布、价格、库存和订单动作由 Owner 批准并留痕；
- **预算与停止线**：实验预算、最大不可回收损失、时间上限、停止触发器；
- **状态与变更控制**：规格、供应商、市场、渠道或法规变化后，自动识别必须重开的闸门；
- **质量与追溯**：样品、批次、验货、投诉、事故、退货、质保和召回关联；
- **风险与异常**：合规、IP、欺诈、隐私、汇率、贸易政策、供应中断和渠道依赖；
- **财务真实性**：actual / quoted / estimated / unknown 分离，利润与现金分开确认；
- **审计与决策理由**：谁基于什么证据，在何时批准、退回、停止或加码。

统一闸门只使用五种结果：`pass`、`conditional`、`return`、`reject`、`expired`。任何节点都不能只剩“完成/未完成”。

## 五、关键闸门

| 闸门 | 必须证明的事情 | 不能冒充证明的代理信号 |
|---|---|---|
| G1 市场信号 | 存在值得形成可证伪假设的变化或问题 | 单个平台热榜 |
| G2 需求问题 | 具体人群在具体情境中承担可观察代价 | 搜索量、点赞、AI 推断 |
| G3 细分机会 | 可识别、可触达、可服务且存在差异空间 | 宏观市场规模 |
| G4 商品规格 | 用户需要已转为可测要求和验证方法 | 供应商图片或现货参数 |
| G5 联合可行性 | 供应、合规、履约、财务和现金风险允许小实验 | 乐观毛利表 |
| G6 实验授权 | Owner 冻结 SKU、预算、终点和停止线 | AI 高置信度 |
| G7 采购放行 | 合同、规格、合规责任和损失边界清楚 | 样品看起来不错 |
| G8 批次/库存放行 | 该真实批次验收合格、可追溯、可售 | 供应商口头承诺 |
| G9 渠道可售 | 主体、收款、价格、库存、内容和规则均成立 | 接口或页面已经开发 |
| G10 有效成交 | 非关联买家付款，订单履约并签收 | 创建订单或支付授权 |
| G11 客户结果闭合 | 退货、拒付、争议和质保观察达到预设终点 | 平台显示已结算 |
| G12 最终净利润 | 收入和全部成本已用真实凭证归集 | 预计贡献利润 |
| G13 现金回收 | 对应现金已可用，未被应收、冻结或准备金占用 | 账面利润为正 |
| G14 经营决策 | 基于利润、现金、客户、质量和机会成本决定下一步 | 只看销量增长 |

## 六、渠道是策略分支，不是闭环本身

平台电商、独立站、批发、分销的共同骨架相同，差异主要发生在：客户触达、合同关系、定价权、库存承诺、支付风险、履约责任、退货规则、结算账期和数据可得性。

因此系统先定义渠道必须提交的标准事实和动作，再由适配器处理平台差异。任何渠道只有在账号/主体、收款、费用、数据权限、合规、履约、退货和结算均可验证时，才有资格承载实验。

## 七、循环不是单向流水线

下列变化必须触发回退或重新放行：

- 客群或使用情境改变：重开需求、规格和合规判断；
- 关键规格改变：重开样品、质量、成本、合规和商品内容；
- 供应商、材料或工厂改变：重开供应商验证、样品、批次与追溯；
- 目标国家或渠道改变：重开准入、税费、物流、定价、支付和售后；
- 退货、投诉或事故超过阈值：暂停销售，进入调查、纠正、召回或退出；
- 成本、汇率、关税或获客价格越界：重算单位经济并重新审批；
- 证据过期：状态改为 `expired`，不能沿用旧结论自动前进。

闭环最终必须允许四类结果：**继续小幅加码、修正后再试、换机会/渠道、停止并退出**。停止不是系统失败；没有留下可复用原因的停止才是失败。

## 八、对凌镜当前方向的含义

完整地图是系统设计的上限，不是当前开发范围。凌镜当前仍应只实现能支撑首轮最小真实实验的最短纵切：

```text
机会证据与反证
→ 可实验商品案件
→ Owner 批准
→ 一次受控供应/渠道/成交/履约
→ 售后闭合
→ 最终净利润与现金回收
→ 继续或停止
```

没有真实实验需求的复杂供应链、全渠道、全税务、全召回和组合优化能力，只保留在领域地图中，不应立即建设。
