# 跨境电商真实流程与凌镜系统设计：三路调研综合

> 日期：2026-07-12
> 用途：为 Owner 单人自营跨境商品业务定义实际流程、最小系统和 AI 分工
> 非目标：不为凌镜寻找外部软件用户，不设计 SaaS 或通用 ERP

## 总裁决

跨境电商的真实流程不是“选品 → 上架 → 出单 → 收款”，而是一条反复排雷、持续返工并最终对账的经营链：

```text
冻结实验边界
→ 市场/渠道/账号/收款预检
→ 候选商品排雷
→ 多供应商询价、样品与合规预检
→ 实测尺寸重量后重算单位经济和最坏损失
→ 小单采购、尾款前质检
→ 分别核验账号、Listing、库存和前台可买
→ 受限预算获取曝光、点击、成交数据
→ 订单风控、履约、签收、售后与争议
→ 平台结算、外部成本、银行回款和汇兑对账
→ 最终利润与现金确认
→ 停止、换品、修正后再试或小幅加码
```

`inferred`：为了跑通这条流程，凌镜当前不需要扩建 AgentOS 或通用 ERP。最小系统应是一条可审计事实链：

```text
experiment
→ order / shipment / after_sale_case
→ settlement_line / payout
→ bank_transaction / external_cost / fx_conversion
→ reconciliation
→ final_profit_record / final_decision
```

## 真实流程中最容易被理想流程隐藏的事实

1. **账号、类目、收款和合规要在采购前验证。** 页面能注册、Listing 能创建、库存已入仓和前台可购买是四个不同事实。
2. **供应商报价不是成本。** 必须拿到样品，实测尺寸重量，加入包装、头程、平台费、广告、退货、税费和汇兑后至少重算三次。
3. **质检要发生在付尾款和离厂前。** 到海外仓后才发现缺陷，返工权和谈判筹码通常已经消失。
4. **首单不是成功。** 有成交仍可能因广告、退货、平台费和低价而亏损。
5. **签收不是结束。** 签收只关闭正向物流，退货、拒付、争议、赔付和晚到费用仍可能改变结果。
6. **平台显示结算不等于银行收到钱。** 平台净额可能包含 reserve、退款、调整和跨期费用；银行到账还可能包含汇兑差额。
7. **利润和现金是两种状态。** 账面利润为正不能证明现金已回收；银行到账也不能证明订单利润为正。

## 系统最小能力

| 能力 | 系统必须保存什么 | 通过条件 |
|---|---|---|
| 候选市场 | 地区、消费者、场景、渠道、八维证据、反证、淘汰条件 | Owner 明确选定，关键项无 unknown |
| 商品机会 | 用途、差异、规格、样品、供应商、合规/IP、成本区间 | 样品和关键可售条件可核验 |
| 实验冻结 | SKU、数量、预算、最大损失、时间窗、主要终点、停止线 | Owner 批准具体参数 |
| 外部动作 | 采购、发布、广告、调价、退款的预览、批准和外部回执 | 不允许超出批准范围 |
| 订单履约 | 订单、付款、批次、发货、轨迹、签收、异常 | 状态来自外部证据且可追溯 |
| 售后争议 | 取消、拒收、退货、退款、拒付、索赔、处置 | 全部关闭或损失已确认 |
| 结算对账 | 结算批次、逐行费用、reserve、payout、银行流水 | 平台净额与银行到账匹配 |
| 最终利润 | 收入、全部实际成本、汇兑、税费、未分配项、计算版本 | 关键 unknown、未分配额和未对账现金均为 0 |
| 异常队列 | 问题、影响对象、最大现金风险、证据、截止时间、建议 | Owner 只处理需要授权或判断的例外 |

## AI 如何工作

AI 不拥有经营事实，也不拥有批准权。它是持续工作的研究员、数据员、对账员和异常助理。

| 阶段 | AI 做什么 | AI 不能做什么 |
|---|---|---|
| 市场与商品研究 | 搜索、抓取、去重、形成候选、找独立反证、标记缺失 | 宣称市场已成立或自动选市场 |
| 权限预检 | 读取账号/API/报表样本，判断能取得哪些字段 | 把连接器存在写成账号可用 |
| 供应与成本 | 比较报价、规格、样品记录，计算情景利润和最坏损失 | 把报价或估算升级为实际成本 |
| 实验准备 | 生成冻结卡、停止条件和待审批动作 | 自己批准采购、发布、广告或扩大预算 |
| 订单与物流 | 去重订单、刷新付款/轨迹、发现冲突和延误 | 在平台与承运商冲突时静默选一个事实 |
| 广告与售后 | 归集花费、监控预算、跟踪退款/拒付/退货 | 自动调价、加预算、退款或补偿 |
| 结算与银行 | 解析逐行费用、候选匹配 payout 与银行交易、解释差额 | 制造调账行、强制平账或忽略未知费用 |
| 最终利润 | 生成可重放利润桥、列出未决项、提出四选一建议 | 在确定性门未通过时声明 final |

每次 AI 输出都应包含：判断对象、主张、事实状态、来源快照、观察时间、假设、反证、缺失字段、建议动作、是否需要 Owner 批准和过期时间。多个 Agent 意见一致仍然只是参考，不能升级为 `actual`。

## 权限边界

- **只读自动**：公开研究、平台/物流/结算/银行数据读取、刷新、去重、计算和预警。
- **建议但不执行**：市场选择、商品选择、供应商比较、成本方案、售后处置、最终经营结论。
- **Owner 批准后执行**：采购、发布、广告、价格、库存、补发、退款、补偿和资金动作。
- **禁止 AI 自动化**：提高预算、改变止损线、伪造缺失事实、强制平账、把 unknown 当 0、把预计利润标成最终利润。

## 最小界面

首轮只需要五个页面：

1. 今日 Owner 队列：审批、异常、止损和待补证；
2. 候选市场比较：同口径证据、反证和 unknown；
3. 实验案卷：冻结参数、预算、时间线和外部动作；
4. 利润与现金桥：订单 → 结算 → 回款 → 银行 → 最终利润；
5. 证据抽屉：任一数字回到原始文件、来源、时间和解析版本。

不需要独立 Agent 驾驶舱。AI 只在具体案件里显示最后刷新、失败原因、下一次重试和是否需要 Owner。

## 推荐的第一个工程闭环

待 Owner 选定一个市场和渠道后，只做一个平台的一笔真实链路：

1. 导入或读取订单、退款、结算原文件和银行流水；
2. 建立 `experiment → order → settlement_line → payout → bank_transaction` 关联；
3. 允许上传供应商、物流、广告、税费和清关凭证作为异常兜底；
4. 输出利润桥和所有未决项；
5. 无法匹配、未知费用和缺证统一进入异常队列；
6. 工程验收是一笔结算完整对到银行，经营结果允许正、零或负。

## 证据等级与未知

- `actual`：三路调研报告已生成；本仓库政策明确凌镜只供 Owner 使用。
- `quoted`：账号卡审、未打样损失、库存入仓不可售、广告有单仍亏、退货与结算错配等来自卖家自述或实操资料，不能直接升级为 Owner 的事实。
- `inferred`：上述流程、最小系统、AI 分工和五页界面是对多份实操材料的综合判断。
- `estimated`：刷新频率、异常优先级和具体界面数量需要真实使用校正。
- `unknown`：Owner 首轮市场、渠道、商品、真实账号权限、物流/平台费用、转化率、退货率和最终利润。
