# 凌镜 Owner 自用经营方向

> 生效日期：2026-07-12
> 状态：当前最高优先级产品方向
> 决策人：Owner

## 一句话定义

> 凌镜是只供 Owner 本人使用的完整 AI 跨境电商经营平台，不服务外部软件用户，也不以软件产品化、对外销售或验证外部软件需求为目标。

唯一开发目标是完整支持 Owner 的跨境商品经营：研究市场、形成机会、管理商品与货源、准备并受控发布渠道内容、经营订单与库存、完成履约和售后、核对结算与最终利润，并让真实结果形成下一次可执行经营决定。完整平台是目的地，按完整纵向单元推进；任何小工具或单次验证都只能是平台组成部分，不能被当成最终产品上限。

## 当前边界

未来 90 天只服务：

- 一个用户：Owner；
- 一个经营主体；
- 零个预设国家、地区、平台、目标客户、类目、商品或固定候选数量；
- Ozon、Shopee、Shopify 及其他现有能力都只是平台连接器；连接器存在不代表对应市场入选；
- 一条事实核验链：`经营决定 → 已批准行动 → 外部发生事实 → 订单与履约 → 售后 → 结算、利润与现金对账`。这只是事实链，不得称为经营闭环或因果实验。

市场选择必须先比较需求强度与反证、竞争与差异化空间、可达到消费者的获客路径、履约、合规、税务、收款、售后和最终利润可验证性。只有市场进入候选短名单后，才验证对应平台账号与数据权限。账号或采集器的现成程度可以影响验证成本，但不能决定市场。

Ozon 不代表欧洲市场，也不代表俄罗斯需求已经成立。历史 Ozon 数据只能用于回答俄罗斯/Ozon 范围内的明确问题；如果本轮候选市场不是俄罗斯/Ozon，这些数据不得进入市场、类目或商品结论。

## 数据采集准入规则

### Owner私人商品收藏例外（2026-07-12新增）

Owner在1688商品页主动点击保存到私人采集箱，属于个人浏览书签/未验证货源线索，不要求事先关联候选市场、目标消费者或经营事实案卷。该例外只为减少浏览时的复制粘贴，不构成决策证据、商品机会、可信货源、已选市场或可上架草稿。

私人采集箱记录必须：

- 标记为 `unverified_lead`，页面字段真实性最高为 `quoted`；
- 与决策证据、经营事实案卷和草稿状态分开；
- 未关联选品任务前不得进入成本、合规、审批、发布、采购或其他经营闸门；
- 只有Owner主动选择继续研究并关联选品任务后，才适用下面的数据采集准入规则；
- 未进入受控经营事实链的私人收藏可以归档或删除；进入后只能按治理规则处理；
- 不得因私人采集箱存在而扩大到整页、整店、批量铺货或自动发布。

因此，下面的“五件事”适用于把数据升级为决策证据、待研究商品或经营输入，不适用于仅保存为私人未验证书签的动作。

每项采集任务开始前必须写清五件事：

1. 它对应哪个候选市场和目标消费者；
2. 它要改变哪个决策：进入、淘汰、继续取证、批准经营行动或停止；
3. 支持与反对该决策分别需要什么字段；
4. 数据的地区、时间、口径、来源和真实性状态；
5. 什么结果会让该市场或假设被淘汰。

不能改变决策的数据不采；只有商品列表、价格或评论而没有地区和决策口径的数据不采；不得因为采集器已经写好就倒推经营目标。

## 首轮资金纪律

- 总现金预算上限：3,000 CNY；
- 不可回收损失硬停止线：1,200 CNY；
- 未取得后台真实费用和退件处置证据前，采购预算为 0；
- 真实发布、采购、广告、库存、订单、退款和资金动作必须由 Owner 批准并留痕；
- 不为降低单价而扩大首批采购量。

## 统一结果定义

- **下单**：买家创建订单，不代表经营成功；
- **有效成交**：非 Owner、非亲友、非供应商的买家付款，订单发出并签收；
- **最终有效成交**：签收后经过适用的退货和争议观察期，没有未决退款、拒付或退货；
- **预计利润**：包含估算或尚未结清项目，只用于决策，不得标记为最终；
- **最终净利润**：以平台结算和真实凭证为准，扣除采购、样品摊销、包装、国内与跨境物流、平台费、广告、折扣、税费、关税、支付提现、汇兑、退款退货、销毁和售后补偿后的结果。

## 唯一允许建设的完整平台范围

- 市场与机会：候选市场、消费者问题、竞争、获客、履约、合规、收款、反证、Owner 决定和商品机会；
- 商品与货源：私人收藏、供应商、样品、成本、合规、图片、内容、SKU 和商品主数据；
- 渠道准备与发布：Listing 草稿、规则验证、Owner 审批、受控发布、状态同步和失败对账；
- 交易经营：订单、库存、采购与补货、履约、物流、售后、退款、争议和异常；
- 经营财务：结算、费用、税费、广告、汇率、订单利润、现金回收和可复算对账；
- 经营决策：具体问题、目标、动作变量、批准、实际执行、观测、偏差、决定和下一动作；
- Owner AI 协作：小Q通过登记 Capability 研究、解释、建议和协调，不绕过确定性领域规则；
- 平台内核：身份、权限、审批、审计、幂等、事件、命令、调度、工具桥、监控、备份、恢复和部署。

## 冻结建设

- 双产品架构与品牌设计；
- 任何外部软件用户、SaaS、客户 onboarding、销售体系或软件需求验证；
- 多租户、订阅、计费、公共 API 和应用市场；
- Evidence Warranty、Outcome Proof 和跨客户知识聚合；
- 未通过数据预检的平台扩张；
- 更多 Agent、MoA 扩张、自治升级和展示性仪表盘；
- 与当前完整纵向单元无关的大型视觉或架构重构。

冻结不等于删除。已有代码可以保留，但不得因为“未来可能需要”进入当前开发队列。

## 唯一开发路线

唯一权威路线是 [ADR-001：完整 Owner 自用跨境电商平台](decisions/ADR-001-owner-complete-commerce-platform.md)：平台真相与领域合同 → 市场与机会 → 商品、货源与渠道准备 → 交易经营 → 经营财务 → 经营决策与反馈 → 小Q统一经营入口 → 生产经营保障。

这是一条依赖路线，不是把平台缩成八个孤立功能。每次选定一个真实纵向流程后，必须把跨层所需的领域模型、API、Owner 体验、权限、审批、审计、失败处理、测试、运行验证和文档一起做完整。现有能力优先复用，错误模型必须迁移或停止；不得为了遵守顺序重复建设已经可信完成的能力。

## 固定产品边界

凌镜保持 Owner 单人自用内部系统。当前没有外部产品解冻门槛，也不安排设计伙伴、客户访谈、软件试点、定价、销售或商业化验证。未来如果 Owner 主动改变这一方向，必须形成一份新的明确决策；真实商品成交或凌镜自用效果不会自动解冻外部产品。

## 当前工程第一任务

> 依据 ADR-001 形成完整平台的目标领域架构和现有能力迁移图，将每个现有模块裁决为复用、改造、迁移、冻结或删除，并选出第一条需要完整交付的纵向流程。该任务是一次性设计门，不得演变成持续内部审计；完成后进入建设。

公开商品、搜索、评论、榜单和竞品只能形成商品经营线索，不能证明真实付款。历史设计和实施计划中的“真实付费需求”仅指商品消费者的真实购买事实，不得解释为凌镜的软件需求或对外产品目标。

## AI 采集原则

- AI 负责发现、抓取、清洗、去重、提出假设、独立反证、刷新和异常重试；
- API 优先，浏览器/ToolBridge 补充公开页面，禁止伪造缺失数据；
- 每个字段保存来源 URL/API、采集时间、采集驱动、原始 payload、解析版本和事实状态；不得用置信分替代真实事件；
- 同一关键事实尽量用两个独立来源交叉验证；冲突时标为 conflict，不静默选值；
- Scheduler 自动刷新会变化的价格、费用、物流、竞争和订单状态；
- Owner 不做日常抄数，只处理登录/验证码、平台授权、AI 无法判定的冲突，以及采购、广告、发布和资金审批；
- 自动采集失败不得阻塞整个批次：重试、换驱动、降级到待复核队列，最后才请求人工补证。
- 平台连接器只能在候选市场和决策问题明确后启用；连接器可用性不能替代市场证据。
