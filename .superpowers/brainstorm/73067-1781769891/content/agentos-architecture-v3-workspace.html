设计第 1 部分最终修订：凌镜 AI 原生经营工作台

新增参考 HTML 后，产品定位进一步收敛：凌镜不是传统 ERP 看板，而是“有受控操作权限的跨境电商 AgentOS 工作台”。

LingMirror = AI Native Commerce Workspace
1. 经营上下文层

@商品 / @SKU / @订单 / @库存 / @店铺 / @平台 / @物流 / @结算

让 Agent 知道“现在在处理什么业务对象”
2. AgentOS 决策层

三个小队：增长 / 履约 / 风控
四级自治：观察 / 建议 / 半自主 / 全自主

让 Agent 像团队一样分工
3. 受控执行层

任务队列 / 审批队列 / 安全红线 / 操作审计 / 回滚复盘

让 AI 能干活，但不能越权
Ask / 查询模式
问经营问题，看解释和分析。不执行操作。
Agent / 协作模式
Agent 生成方案、任务和变更，人审批后执行。
Quest / 委托模式
用户设目标，Agent 后台跑完整工作流，异常时打断。
产品表面
Web 总控台是第一版主入口；后续可扩展桌面端处理本地文件/表格，IM/移动端用于远程审批和日报。
技能生态
运营 SOP、选品策略、定价规则、上架流程沉淀为 Skills；第一版先做内置技能和规则，不做开放市场。

相对上一版的新增点

1. 从“总控台”升级为“AI 原生工作台”。总控台仍是首页，但产品心智不是看报表，而是把业务目标交给受控 Agent 团队执行。

2. 增加三种工作模式。Ask 负责查和解释，Agent 负责协作执行，Quest 负责端到端委托。它们对应用户信任逐步提升的过程。

3. 明确 Web / 桌面 / IM 的长期分工。第一版做 Web；桌面端未来负责本地文件、Excel、图片素材、浏览器自动化；IM/移动端只做派单、提醒、审批、结果查看。

4. 技能系统作为长期护城河。跨境电商的 SOP、规则、经验不能只存在于配置项里，要逐步变成可复用、可审计、可分享的运营技能。

第一版产品承诺

  • 用户能在一个工作台看到全业务任务、风险、审批和 Agent 状态。
  • 用户能明确控制每个 Agent 的自治等级。
  • Agent 的每次建议和执行都有上下文、理由、风险、审计。
  • 至少一条业务链路能从目标到执行闭环跑通。

不是第一版承诺

  • 不是完整桌面端。
  • 不是开放 Skill 市场。
  • 不是所有平台 API 全自动操作。
  • 不是所有 Agent 都达到全自主。
