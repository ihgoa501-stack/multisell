# 经营学习的个人化边界：Owner-only 前提下的未来决策框架

> 日期：2026-07-13
> 类型：内部研究，不是产品方向变更、技术方案或开发授权
> 当前边界：凌镜仍然只供 Owner 本人使用；外部 SaaS、多租户、订阅、计费、公共 API 和外部 onboarding 继续冻结
> 研究问题：如果未来真的出现不同使用者，系统应如何区分个人上下文、个人经验、共享事实和群体规律，避免把“循环学习”做成混用数据或放大偏差

## 1. 结论

未来即使出现不同使用者，学习的基本单位也不应是“所有人的数据池”，而应是：

> **某个明确的人，在某个经营上下文中，面对一个具体问题，基于当时证据形成构思，经本人决定和实际行动后，观察结果并更新只属于该上下文的经验。**

因此必须先分开五种东西：

1. **目标**：这个人本次希望改善什么，以及观察期限。
2. **约束**：不能违反的硬边界，例如预算、现金、安全、合规和库存上限。
3. **偏好**：可以权衡的软取舍，例如利润、速度、风险和工作量之间的倾向。
4. **客观上下文**：当时外部和经营事实，例如平台规则、成本、库存和订单状态。
5. **个人经验**：这个人过去在相似上下文中做过什么、结果怎样。

`inferred`：这五类信息混在一个“用户画像”里，会让系统无法解释一次建议究竟来自事实、硬约束、个人偏好还是历史相关性，也无法在目标变化后正确停止沿用旧经验。

`policy`：当前只实现和验证 Owner 自己的经营学习，不为假设中的第二个人建设账户体系、租户隔离、跨用户训练或群体推荐。

## 2. 什么叫“构思”

本研究建议把“构思”理解为一个**带上下文的可检验经营设想**，不是事实、规则或自动命令：

> 在冻结的事实、目标、约束和偏好下，提出一个具体动作，说明预期结果、观察期限、风险、停止条件和仍然未知的事项。

一份构思只有在以下信息能够区分时才完整：

| 内容 | 回答的问题 | 性质 |
|---|---|---|
| 决策主体 | 这是谁的经营问题？ | 身份与授权 |
| 目标 | 想改善什么、在多久内改善？ | 本次意图 |
| 约束 | 哪些边界不能突破？ | 硬门禁 |
| 偏好 | 多个可行方案之间怎样取舍？ | 软排序 |
| 事实快照 | 当时实际知道什么？ | 有来源和时间的证据 |
| 建议动作 | 建议改变哪个可执行变量？ | `inferred` |
| 预期与期限 | 预计何时出现什么结果？ | 待验证预测 |
| 决定与执行 | 本人批准了什么、实际发生了什么？ | 决定与外部凭证 |
| 结果与反证 | 结果支持、反对、冲突还是不足以判断？ | 观察，不自动等于因果 |

`quoted`：情境老虎机研究把个性化决策表达为“根据用户和候选内容的上下文选择动作，再根据收到的反馈调整策略”，说明学习必须绑定当时上下文和实际暴露，而不是只累计结果。[Li et al., 2010](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/p661.pdf)

`inferred`：对凌镜而言，“构思”应是经营决策案卷中的建议层；Owner 决定、外部执行和结果观察仍应分别保存，不能压成一个会自行更新的万能对象。

## 3. 三类记忆不能混用

### 3.1 个人上下文与个人经验

默认只服务本人，包括：

- 本人的目标、风险承受、预算和现金约束；
- 本人的偏好、否决和修改；
- 本人的供应商关系、成本、订单、利润和现金；
- 系统给本人展示过什么、本人选择了什么、实际做了什么；
- 由以上经历产生的个人经验和下一次建议。

`inferred`：这些数据即使去掉姓名，也可能通过商品、渠道、时间、供应商或经营轨迹重新指向本人，因此不能仅凭“匿名字段”就升级为可共享数据。

### 3.2 可共享的客观事实

未来可以考虑共享的不是“别人做什么有效”，而是可独立核验的外部事实，例如：

- 平台公开规则及其生效时间和适用地区；
- 法规、费率、汇率或物流公开信息；
- 经授权取得、保留来源和观察时间的外部事件；
- 不含个人经营结果的通用计算规则。

即使属于客观事实，也必须保留来源、时间、适用范围、真实性和失效条件；不同人的判断仍要重新套用各自目标和约束。

### 3.3 群体规律

群体规律是“多个独立个体在可比上下文中的统计结论”，不是把个人案例放在一起检索。只有同时满足下列条件才可进入候选：

1. 存在真实第二位及以上使用者，而不是假设；
2. 当前 Owner-only 政策已由 Owner 明确变更；
3. 每个人明确知道共享目的、范围和退出方式，并有可证明的授权；
4. 原始个人数据默认隔离，聚合前有最小样本、重识别和泄漏风险评估；
5. 结论按上下文分层，报告样本量、不确定性、适用范围和反证；
6. 群体规律只能作为低优先级先验，不能覆盖个人硬约束、个人事实或本人决定；
7. 独立验证证明共享确实改善判断，而不是只提高点击、接受率或模型自信。

`quoted`：联邦学习原始论文展示了“数据留在各客户端，只聚合本地更新”的一种共享学习方式，同时指出实际数据通常不平衡且非独立同分布；它证明“原始数据不集中”在技术上可行，但不等于已经解决同意、重识别或隐私泄漏。[McMahan et al., 2017](https://proceedings.mlr.press/v54/mcmahan17a.html)

`quoted`：NIST SP 800-226 将差分隐私定义为可量化某个个体数据进入数据集时隐私损失的数学框架。这说明如果未来真的发布群体统计，必须有可评估的隐私保证，不能只写“已匿名”。[NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final)

`policy`：上述群体学习条件目前均不构成开发需求。

## 4. 为什么目标、约束和偏好必须分离

| 类型 | 例子 | 系统如何使用 | 变化后的处理 |
|---|---|---|---|
| 目标 | 30 天内释放库存现金 | 决定评价指标和期限 | 新目标开启新一轮，不回写旧轮次 |
| 约束 | 不能低于最低贡献利润；采购不超过 5,000 元 | 先过滤不可执行动作 | 违反即阻断，不能被历史成功率覆盖 |
| 偏好 | 在利润相近时更偏好低库存风险 | 对可行方案排序 | 可修改，但保留当时版本 |
| 上下文 | 当前库存、成本、平台费率、季节 | 判断历史案例是否可比 | 以时间化事实快照保存 |
| 经验 | 过去相似条件下的行动和结果 | 提供参考和反证 | 只在可比范围内降权或复用 |

`quoted`：NIST AI RMF 要求理解并记录 AI 系统的预期用途、可能受益用途、适用场景、相关规范和期望，并要求输出在已识别的上下文中解释。这支持“先确定用途和上下文，再解释学习结果”，而不是先形成全局规律再寻找适用对象。[NIST AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)

`inferred`：如果某个人从“追求利润”改为“快速回笼现金”，旧结果仍是历史事实，但旧奖励标准已经失效；系统应该重新评价，而不是删除或偷偷改写旧经验。

## 5. 隐私、授权和隔离的决策边界

如果未来出现其他使用者，以下不是可选优化，而是进入多人学习之前的前置决策：

- **目的限定**：每类数据明确用于个人服务、客观事实共享还是群体学习，不能事后自动改用途；
- **数据最少化**：只处理实现该目的必要的数据；
- **可理解授权**：授权内容与其他条款分开说明，能够证明，撤回应与授权同样容易；
- **访问隔离**：身份、授权、数据读取、模型更新、导出和删除均按人隔离；
- **生命周期控制**：本人能够查看、更正、导出或删除属于自己的个人数据及可分离的派生记录；
- **模型边界**：必须知道一条建议使用了个人经验、共享事实还是群体先验，并能关闭群体先验；
- **敏感输出保护**：群体结果不能反推出某个具体人的供应商、销量、利润、现金或行为。

`quoted`：GDPR 第 5 条明确规定目的限定、数据最少化和准确性；第 7 条要求在依赖同意时能够证明同意，并允许随时撤回且撤回应与给予同意一样容易。这不是对凌镜适用法律的判断，但可作为未来多人数据治理的最低设计参照。[GDPR Article 5](https://eur-lex.europa.eu/eli/reg/2016/679/art_5/oj/eng)；[GDPR Article 7](https://eur-lex.europa.eu/eli/reg/2016/679/art_7/oj/eng)

`quoted`：NIST Privacy Framework 建议先盘点数据处理活动、隐私风险、价值和法律要求，再确定目标状态；其控制映射还要求访问权限遵守最小权限和职责分离。[NIST Privacy Framework 1.1](https://www.nist.gov/privacy-framework/using-privacy-framework-11)；[NIST Privacy Control Map](https://www.nccoe.nist.gov/publication/1800-28/VolB/vol-b-appendix.html)

`unknown`：未来是否出现其他使用者、在哪个司法辖区、处理哪些个人或商业数据，目前都不知道，因此本文不能给出合规结论。

## 6. 冷启动：没有个人历史时怎样学习

冷启动不是缺少一个更大模型，而是系统还没有足够证据理解这个人的目标和偏好。

`quoted`：冷启动研究指出，只有协同历史的推荐系统在新用户或新项目上会失败；内容和用户属性可以帮助跨过最初缺口，但没有属性时仍缺乏个性化依据。[Schein et al., 2002](https://dpennock.com/papers/schein-sigir-2002-cold-start.pdf)

因此未来新使用者的默认顺序应是：

1. 先让本人明确目标、硬约束、观察期限和少量关键偏好；
2. 使用可验证的客观事实和通用计算规则；
3. 把群体规律标为低置信度先验，不冒充个人经验；
4. 提供保守基线和“暂不建议”，不为了收集反馈强推高风险动作；
5. 从少量、可逆、经本人批准的动作中获得个人证据；
6. 只有重复、可比的个人经历才逐步提高个性化权重。

`inferred`：对当前 Owner 来说，冷启动仍然存在，因为尚无真实行动和后续经营结果；其他人的数据不能替代这条缺失的个人证据。

## 7. 反馈偏差：系统可能学到自己制造的结果

循环学习的最大风险之一，是系统只看到“自己推荐并被执行的动作”的结果，却看不到未展示、未选择或未执行的反事实。

`quoted`：从历史日志学习属于带偏反馈问题，系统只能观察已选动作的结果；反事实风险最小化研究因此使用展示概率等信息修正偏差，并显式控制估计方差。[Swaminathan & Joachims, 2015](https://proceedings.mlr.press/v37/swaminathan15.html)

`quoted`：关于人与推荐系统交互的原始研究证明，推荐会改变未来收集到的数据，忽略这种反馈循环的朴素估计可能不一致。[Schmit & Riquelme, 2018](https://proceedings.mlr.press/v84/schmit18a.html)

对经营学习的决策含义是：

- 必须保存系统展示过哪些构思、为什么展示以及哪些没有被选中；
- “Owner 接受建议”只能证明接受发生，不证明建议正确；
- “行动后结果变好”只能先记为 `support`，不能自动写成因果；
- 未执行、执行失败、观察窗口不足和外部环境变化必须分别记录；
- 同一策略长期只展示同一种动作，会让系统越来越确信自己已有的偏好；
- 任何自动评价都需要保留无动作基线、外部变化、选择机制和不确定性。

## 8. 是否允许跨人学习的决策门

未来只有以下问题全部回答“是”，才值得进入跨人学习设计：

| 决策问题 | 未通过时的结论 |
|---|---|
| 是否已经存在真实第二位使用者和明确问题？ | 不建设 |
| Owner 是否明确改变 Owner-only 政策？ | 不建设 |
| 共享能否改善一个具体、可测量的判断？ | 保持个人学习 |
| 是否能把客观事实、个人经验和群体规律分开？ | 禁止汇总 |
| 每个人是否获得清楚、可撤回的控制权？ | 禁止用于学习 |
| 是否有足够独立且可比的样本？ | 只报告 unknown |
| 是否记录暴露、选择和未执行结果以识别反馈偏差？ | 不得声称学习有效 |
| 是否能证明隔离、删除、导出和聚合泄漏边界？ | 禁止上线 |
| 群体先验是否始终低于个人约束和本人决定？ | 禁止自动应用 |

## 9. 当前对凌镜的建议

### 保留

- `policy`：继续建设 Owner 自用完整平台。
- `policy`：事实、AI 建议、Owner 决定、实际行动和结果观察继续分层。
- `inferred`：把目标、约束、偏好和上下文作为每次经营构思的明确输入，比建设一个笼统“用户画像”更可解释。
- `inferred`：学习结果首先更新 Owner 自己的经营经验；客观事实可以复用，但不能替代本人的结果。

### 暂不建设

- 多用户账户和租户隔离；
- 跨用户行为数据池；
- 群体画像、协同过滤或联邦学习；
- 以接受率、点击率或一次利润自动更新全局策略；
- 任何“匿名后默认共享”的机制。

### 触发重新研究的条件

只有出现真实第二位使用者，并由 Owner 明确考虑改变当前方向时，才重新研究：适用法律、身份与租户模型、授权撤回、数据导出删除、聚合隐私保证、样本门槛、偏差评估和事故响应。

## 10. 尚未解决的问题

- `unknown`：Owner 本人希望长期优化的目标是否稳定，还是会随资金、阶段和商品变化。
- `unknown`：哪些偏好需要 Owner 明确表达，哪些可以从重复行为中谨慎推断。
- `unknown`：怎样判定两个经营上下文足够相似，可以复用历史经验。

- `unknown`：未来是否会有第二位软件使用者；当前没有证据支持为此建设。
- `unknown`：任何未来多人形态的司法辖区、合规义务和风险成本。

## 11. 来源性质与证据限制

本文优先使用原始论文、官方标准和法规原文。论文证明其研究设定中的方法或风险，不直接证明凌镜采用同样方法会有效；法规引用只作为设计参照，不构成法律意见。本文没有修改代码、运行模型、连接生产数据或验证真实经营学习效果。
