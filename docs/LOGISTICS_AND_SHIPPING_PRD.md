# MultiSell 物流与运费 PRD

> 产品需求文档 · 2026-06-14
> 状态：第三阶段已实现基础物流字段、运费计算、订单运费快照与利润一期

---

## 1. 背景

MultiSell 当前已具备商品、SKU、价格、库存、供应商、订单等基础模块。但在物流和运费维度上存在关键空白：

- **商品和 SKU 没有包装尺寸和重量字段**——当前 `Sku` 模型仅有 `weight` 字段，且无长宽高，无法计算体积重。
- **运费无法自动计算**——运营人员需要手动判断运费，或依赖外部工具。
- **供应商物流渠道无管理**——无法对比不同供应商 / 承运商的报价和时效。

跨境电商的运费在商品总成本中占比可观（尤其是体积大、重量轻的"抛货"），且不同物流渠道报价差异显著。为了让后续的订单利润分析和多平台定价决策可靠，物流和运费数据必须被系统化管理。

### 1.1 为什么必须区分商品尺寸和包装尺寸

- **商品尺寸**（product dimensions）是商品本身的物理尺寸，用于描述商品、确定产品规格。
- **包装尺寸**（package dimensions）是发货时实际包裹的尺寸，直接决定运费。
- 同一商品可能在不同场景使用不同包装（如单件发 vs 多件装箱），运费以包装尺寸为准。

### 1.2 为什么需要 SKU 级覆盖

- 同一商品不同 SKU（如不同颜色、尺寸）的包装可能不同。
- 如果 SKU 有独立的包装数据，应以 SKU 为准；否则回退到商品级默认包装数据。

---

## 2. 目标

1. **商品和 SKU 可存储物流属性**：包装长宽高 + 重量 + 商品尺寸。
2. **运营人员可识别哪些商品缺少运费必要数据**：系统标记物流数据不完整。
3. **系统可自动计算预估运费**：基于包装尺寸、计费重和供应商报价规则。
4. **可对比多家供应商 / 物流渠道的运费和时效**：支持运营选择最优方案。
5. **订单可快照运费计算结果**：记录最终选用的渠道和运费明细。

---

## 3. 非目标（第一期不实现）

- ✗ 不接入真实物流承运商 API（如 DHL、云途 API 直连）。
- ✗ 不做仓库装箱优化（如何将多个商品组合装箱最小化运费）。
- ✗ 不做运费对账 / 财务结算系统。
- ✗ 不做实时物流轨迹追踪。

> 补充说明：当前已落地 `Product` / `Sku` 物流基础字段、物流完整性状态、供应商/渠道/报价规则、运费计算、订单运费快照和利润一期测算；真实承运商 API、装箱优化、面单/追踪和运费对账另行排期。

| 角色 | 核心职责 |
|---|---|
| **商品运营**（Product Operator） | 录入和维护商品/SKU 的包装尺寸、重量、商品尺寸 |
| **物流运营**（Logistics Operator） | 维护供应商物流渠道、报价规则、目的地覆盖 |

## 5. 业务流程

### 5.1 数据维护流程

```
商品运营
  ├─ 创建/编辑商品 → 填写商品尺寸 + 包装尺寸 + 包装重量
  ├─ 创建/编辑 SKU → 可选覆盖包装尺寸 + 包装重量
  └─ 商品列表 → 查看物流完整状态

物流运营
  ├─ 维护供应商物流渠道
  ├─ 配置渠道支持的目的地国家/区域
  ├─ 配置报价规则（首重、续重、阶梯价、附加费等）
  └─ 配置可承运货品类型（普通、带电池、液体、敏感品）
```

### 5.2 运费计算流程

```
1. 用户选择 SKU + 数量 + 目的地国家（可选邮编）
2. 系统解析 SKU 或商品包装数据
3. 系统计算体积重和计费重
4. 系统检索可用物流渠道
5. 检查货品类型限制（如电池品不能走普货渠道）
6. 按报价规则计算各渠道运费
7. 排序并返回比较结果（含费用明细和时效）
8. 用户选择渠道 → 生成运费快照
```

### 5.3 订单运费记录

```
1. 订单详情中可调用运费计算并保存最低价或指定渠道报价
2. 系统保存 `sales_order_shipping_snapshot` 历史快照
3. `sales_order.shipping_fee` 同步为当前快照的总运费
4. 订单详情展示运费快照和利润测算
5. 报价规则后续变化不影响历史订单运费
```

## 6. 商品物流字段需求

### 6.1 商品级字段（Product 表新增）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product_length_cm` | `Decimal(10,2)` | 否 | 商品长度 (cm) |
| `product_width_cm` | `Decimal(10,2)` | 否 | 商品宽度 (cm) |
| `product_height_cm` | `Decimal(10,2)` | 否 | 商品高度 (cm) |
| `product_weight_kg` | `Decimal(10,2)` | 否 | 商品重量 (kg) |
| `package_length_cm` | `Decimal(10,2)` | **是** | 包装长度 (cm) |
| `package_width_cm` | `Decimal(10,2)` | **是** | 包装宽度 (cm) |
| `package_height_cm` | `Decimal(10,2)` | **是** | 包装高度 (cm) |
| `package_weight_kg` | `Decimal(10,2)` | **是** | 包装总重 (kg，含商品+包装材料) |
| `cargo_type` | `String(50)` | 否 | 货品类型：`normal`/`battery`/`liquid`/`sensitive`，默认 `normal` |

> **说明**：`package_weight_kg` ≠ `product_weight_kg`——包装重量包含商品、内衬、纸箱/快递袋等所有发货物料的重量。

### 6.2 SKU 级覆盖字段（Sku 表新增）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sku_length_cm` | `Decimal(10,2)` | 否 | SKU 包装长度覆盖 |
| `sku_width_cm` | `Decimal(10,2)` | 否 | SKU 包装宽度覆盖 |
| `sku_height_cm` | `Decimal(10,2)` | 否 | SKU 包装高度覆盖 |
| `sku_weight_kg` | `Decimal(10,2)` | 否 | SKU 包装重量覆盖 |

> **覆盖规则**：SKU 字段非空时使用 SKU 值，否则回退到商品级包装字段。

### 6.3 物流数据完整性

商品被视为"物流数据不完整"的条件：

- `package_weight_kg` 为空或 0
- `package_length_cm`/`package_width_cm`/`package_height_cm` 任一为空或 0

**商品列表中应展示物流数据状态标签**：`物流完整` / `物流不完整`。

## 7. 商品列表展示需求

商品列表 / 详情应展示以下物流信息（基于商品级或 SKU 级包装数据）：

| 展示项 | 说明 |
|---|---|
| 包装重量 | `package_weight_kg` |
| 包装尺寸 | `L × W × H cm` |
| 体积重 | `L × W × H ÷ 6000`（抛重系数取决于渠道，默认显示 6000） |
| 计费重 | `max(实际重量, 体积重)` |
| 物流状态 | `物流完整` / `物流不完整` |

## 8. 供应商与物流渠道需求

### 8.1 物流渠道（ShippingChannel）

每个物流渠道对应一个供应商下的具体物流产品。

| 字段 | 说明 |
|---|---|
| 所属供应商 | 绑定 `supplier.id` |
| 渠道名称 | 如"美国普货"、"欧洲带电" |
| 支持目的地 | 国家列表 + 可选邮编范围 |
| 抛重系数（volumetric divisor） | 常见值 5000 / 6000 / 8000 |
| 报价规则类型 | 见第 9 节 |
| 支持货品类型 | `normal`/`battery`/`liquid`/`sensitive` |
| 预计时效 | 如 7-15 天 |
| 币种 | 如 `CNY`/`USD` |
| 状态 | 启用 / 禁用 |

### 8.2 供应商与渠道关系

```
供应商（如：云途物流）
  ├─ 渠道：美国普货（支持 US，抛重比 6000，可发 normal）
  ├─ 渠道：欧洲专线（支持 DE/FR/IT/ES，抛重比 6000，可发 normal+battery）
  └─ 渠道：美国带电（支持 US，抛重比 5000，可发 battery）

供应商（如：燕文物流）
  ├─ 渠道：燕文美国小包（支持 US，抛重比 8000，可发 normal）
  └─ 渠道：燕文欧洲小包（支持 DE/UK/FR，抛重比 8000，可发 normal）
```

## 9. 报价规则需求

系统需支持以下报价规则类型：

### 9.1 固定费 + 每公斤价（`fixed_plus_per_kg`）

```
运费 = 固定费 + 计费重 × 每公斤价格
```

### 9.2 首重 + 续重（`first_weight_plus_increment`）

```
运费 = 首重价格 + ceil((计费重 - 首重) / 续重单位) × 续重单价
```

常见于小包物流（如首重 100g = 20 CNY，续重 100g = 5 CNY）。

### 9.3 阶梯重量（`tiered_weight`）

```
根据计费重所在区间直接取对应价格
```

| 重量区间 | 价格 |
|---|---|
| 0–0.5 kg | 35 CNY |
| 0.5–1 kg | 48 CNY |
| 1–2 kg | 70 CNY |
| 2–5 kg | 110 CNY |

### 9.4 最低收费（`minimum_charge`）

作为规则的附加约束，当按规则计算出的运费低于最低收费时，按最低收费收取。

### 9.5 附加费 / 附加百分比（`surcharge` / `fuel_surcharge`）

- 附加费可以是固定金额（如偏远地区附加费 20 CNY）。
- 燃油附加费按运费百分比计算（如当前燃油附加费 15%）。

### 9.6 以上规则可组合

例如：`fixed_plus_per_kg` + `minimum_charge` + `fuel_surcharge`。

## 10. 运费计算输出

运费计算接口应返回以下信息（支持多渠道对比）：

| 输出项 | 说明 |
|---|---|
| 供应商名称 | 如"云途物流" |
| 渠道名称 | 如"美国普货" |
| 目的地 | 国家 + 邮编（可选） |
| 实际重量 | kg |
| 体积重 | kg（含抛重系数） |
| 计费重 | kg |
| 运费基础费用 | 根据报价规则计算 |
| 附加费明细 | 各项附加费 |
| 燃油附加费 | 百分比计算 |
| 运费总计 | 最终总运费 |
| 币种 | 如 CNY |
| 预计时效 | 如 7-15 天 |
| 计算说明 | 人类可读的计算步骤 |

## 11. 验收标准

1. 商品必须填写包装重量和包装尺寸才能被认为是"物流完整"。
2. SKU 可以覆盖商品的包装数据；SKU 字段为空时回退到商品级数据。
3. 运费计算器可以同时对比多个供应商的多个渠道。
4. 运费计算结果包含可读的费用分项说明。
5. 订单可以保存运费快照（选择的渠道 + 运费明细）。✅ 已实现
6. 订单详情返回并展示 `shipping_snapshot`。✅ 已实现
7. 订单详情返回并展示 `profit`，支持 `product_cost`、`platform_fee`、`payment_fee`、`other_fee` 输入。✅ 已实现
