# 凌镜 Owner 自用经营方向

> 生效日期：2026-07-11
> 状态：当前最高优先级产品方向
> 决策人：Owner

## 一句话定义

> 凌镜是 Owner 本人发现和验证真实付费需求的内部经营系统；最终形态由真实使用决定，不面向外部客户。

当前唯一目标是先从跨市场证据中选出一个值得测试的“国家/地区 × 目标消费者 × 需求场景 × 销售渠道”，再提出需求假设、强制独立 AI 寻找反证，并由 Owner 批准最小真实实验。只有非关联买家的付款、签收、售后窗口结束和正的最终贡献利润同时成立，系统才允许写“发现了真实付费需求”。

## 当前边界

未来 90 天只服务：

- 一个用户：Owner；
- 一个经营主体；
- 零个预设国家、地区、平台、目标客户、类目、商品或固定候选数量；
- Ozon、Shopee、Shopify 及其他现有能力都只是平台连接器；连接器存在不代表对应市场入选；
- 一条结果链：`真实数据 → 需求假设 → 独立反证 → 可实验案件 → Owner 批准 → 真实付款 → 签收与售后闭合 → 正的最终贡献利润`。

市场选择必须先比较需求强度与反证、竞争与差异化空间、可达到消费者的获客路径、履约、合规、税务、收款、售后和最终利润可验证性。只有市场进入候选短名单后，才验证对应平台账号与数据权限。账号或采集器的现成程度可以影响验证成本，但不能决定市场。

Ozon 不代表欧洲市场，也不代表俄罗斯需求已经成立。历史 Ozon 数据只能用于回答俄罗斯/Ozon 范围内的明确问题；如果本轮候选市场不是俄罗斯/Ozon，这些数据不得进入市场、类目或商品结论。

## 数据采集准入规则

每项采集任务开始前必须写清五件事：

1. 它对应哪个候选市场和目标消费者；
2. 它要改变哪个决策：进入、淘汰、继续取证、批准实验或停止；
3. 支持与反对该决策分别需要什么字段；
4. 数据的地区、时间、口径、来源和真实性状态；
5. 什么结果会让该市场或假设被淘汰。

不能改变决策的数据不采；只有商品列表、价格或评论而没有地区和决策口径的数据不采；不得因为采集器已经写好就倒推经营目标。

## 首轮资金纪律

- 总现金预算上限：3,000 CNY；
- 不可回收损失硬停止线：1,200 CNY；
- 未取得后台真实费用和退件处置证据前，采购预算为 0；
- 真实发布、采购、广告、库存、订单、退款和资金动作必须由 Owner 批准并留痕；
- 不为降低单价而扩大首批采购量。

## 统一结果定义

- **下单**：买家创建订单，不算实验成功；
- **有效成交**：非 Owner、非亲友、非供应商的买家付款，订单发出并签收；
- **最终有效成交**：签收后经过适用的退货和争议观察期，没有未决退款、拒付或退货；
- **预计利润**：包含估算或尚未结清项目，只用于决策，不得标记为最终；
- **最终净利润**：以平台结算和真实凭证为准，扣除采购、样品摊销、包装、国内与跨境物流、平台费、广告、折扣、税费、关税、支付提现、汇兑、退款退货、销毁和售后补偿后的结果。

## 允许建设

- 需求案件、原始证据、独立反证、确定性裁决和六行 Owner 决策卡；
- 商品实验、预算、现金账本、停止规则和触发记录；
- 成本来源状态：`actual / quoted / estimated / unknown`；
- 经实证平台的单实验流量、订单、支付、物流、退货和结算关联；
- 有效成交与最终有效成交状态；
- 实验级最终净利润以及停止、换品、修正后再试、小幅加码四种结论；
- AI 自动采集市场、供应商、费用、物流、订单、退货和结算证据；人工录入只作为采集失败后的异常兜底，并必须标明来源与原因。

## 冻结建设

- 双产品架构与品牌设计；
- 外部 SaaS、外部客户 onboarding 和销售体系；
- 多租户、订阅、计费、公共 API 和应用市场；
- Evidence Warranty、Outcome Proof 和跨客户知识聚合；
- 未通过数据预检的平台扩张；
- 更多 Agent、MoA 扩张、自治升级和展示性仪表盘；
- 与前三轮真实实验无关的大型视觉或架构重构。

冻结不等于删除。已有代码可以保留，但不得因为“未来可能需要”进入当前开发队列。

## 开发路线

1. **Sprint 0：事实源归一**——删除预设国家、平台、客户、类目、商品和固定漏斗数量，冻结证据等级与裁决语言。
2. **Sprint 1：候选市场比较**——用同一框架比较国家/地区、消费者、需求场景与渠道，并强制记录反证和淘汰条件。
3. **Sprint 2：已入围市场的数据预检**——只验证候选短名单所需的数据源、账号和权限，不能用代码存在冒充市场可行。
4. **Sprint 3：自动研究循环**——三个独立 AI run 负责侦察、反证和数据现实审计，只产出待验证案件。
5. **Sprint 4：Owner 批准的最小真实实验**——另行冻结 SKU、预算、流量、主要终点和停止条件后才允许外部动作。
6. **Sprint 5：终局与复验**——完成付款、签收、售后、结算和正贡献裁决；两轮真实使用后才决定软件化范围。

## 外部产品解冻门槛

只有同时满足以下条件，才可讨论 3–5 个高接触外部设计伙伴；不得直接恢复公共 SaaS：

1. 至少三轮完整真实实验，至少一个商品达到预设加码条件；
2. Owner 连续八周使用核心闭环；
3. 流程在两个类目或两个批次中复现；
4. 五位无利益关系卖家看过真实流程，三位愿意提供数据试用，两位愿意付费或签有价格的试点意向；
5. 能区分 Owner 特有能力与可通用能力；
6. 自营实验累计最终净利润为正，或软件试点获得真实预付款。

## 当前工程第一任务

> 建立 AI 驱动的跨市场选择与真实付费需求发现循环：先比较并淘汰候选市场，再针对已选市场形成有来源的假设，强制独立反证，用确定性状态机阻止代理信号跨级，最后用 `experiment_id` 串联 Owner 批准、流量、订单、支付、物流、售后、结算与最终贡献利润。

公开商品、搜索、评论、榜单和竞品只能形成线索，不能证明真实付款。完整边界见 [真实付费需求发现循环设计](superpowers/specs/2026-07-11-paid-demand-discovery-loop-design.md) 和 [实施计划](superpowers/plans/2026-07-11-paid-demand-discovery-loop.md)。

## AI 采集原则

- AI 负责发现、抓取、清洗、去重、提出假设、独立反证、刷新和异常重试；
- API 优先，浏览器/ToolBridge 补充公开页面，禁止伪造缺失数据；
- 每个字段保存来源 URL/API、采集时间、采集驱动、原始 payload、解析版本和事实状态；不得用置信分替代真实事件；
- 同一关键事实尽量用两个独立来源交叉验证；冲突时标为 conflict，不静默选值；
- Scheduler 自动刷新会变化的价格、费用、物流、竞争和订单状态；
- Owner 不做日常抄数，只处理登录/验证码、平台授权、AI 无法判定的冲突，以及采购、广告、发布和资金审批；
- 自动采集失败不得阻塞整个批次：重试、换驱动、降级到待复核队列，最后才请求人工补证。
- 平台连接器只能在候选市场和决策问题明确后启用；连接器可用性不能替代市场证据。
