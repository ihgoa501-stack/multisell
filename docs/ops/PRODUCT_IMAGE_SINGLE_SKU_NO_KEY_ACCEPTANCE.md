# 商品图片单 SKU 无 Key 验收手册

> 状态：`ready_for_owner_inputs`
> 最后核验：2026-07-13
> 目标：不用任何图片 Provider Key，以一个真实 SKU 完成一次“原图 → 确定性候选 → 反馈/返工 → Owner 批准 → 配方汇总”闭环

## 开始条件

准备以下真实输入：

1. 一个已存在于凌镜的 exact SKU；
2. 一张 Owner 有权复制和修改的真实商品 PNG/JPEG；
3. 权利证据文件及其 SHA-256；
4. 一个真实用途和渠道；首轮推荐 `scene_gallery`，但原图本身必须已经是真实场景照片；
5. 如需进入图片集合，准备属于同一 Owner、商品和渠道的真实 Listing ID。

没有真实 SKU、图片权利或可靠商品事实时停止，不用 mock 补齐。

macOS 可在终端计算证据文件哈希：

```bash
shasum -a 256 /绝对路径/权利证据文件
```

## 环境检查

1. 按 [`OWNER_AND_AI_DEPLOYMENT_RUNBOOK.md`](OWNER_AND_AI_DEPLOYMENT_RUNBOOK.md) 启动受控环境；
2. 登录 Owner 账号并打开 `/product-images`；
3. 页面必须显示 `deterministic（本地）· 可用`；
4. OpenAI、Photoroom 不可用不影响本次验收；不要配置或粘贴 Key；
5. 能在“准确 SKU”下拉框找到本次真实 SKU，否则先回到商品/SKU 模块建立真实记录。

## 页面操作

1. 上传真实原图，记录页面返回的图片 SHA-256；
2. 选择 exact SKU、`deterministic`、`DETERMINISTIC_RESIZE`、真实用途和渠道；
3. 填写场景结构、模型 `deterministic`、版本 `1`、参数 `{}` 和不能改变的商品事实；
4. 填写授权人、权利来源、证据 SHA-256，确认复制权、修改权和 Owner 核验；
5. 保存原图处理权利，创建并执行确定性图片任务；
6. 打开候选原尺寸，对照原图和实物/可靠规格检查结构、颜色、Logo、文字、数量及配件；
7. 保存候选反馈：
   - 可用：选择 `selected`；
   - 不可用：选择 `rejected` 并记录原因；
   - 需要修改：选择 `rework_requested`，写明要求，再点击“载入为返工配方”创建下一版本；
8. 填写实际人工审核秒数；如有外部现金成本，保存 `actual` 成本和证据；纯本地确定性处理可记录为 `0`；
9. 对最终候选保存精确输出权利和五类审核；证据等级按实际情况填写，不能把推断写成 `actual`；
10. 如有真实 Listing，创建图片集合、冻结 Owner 选择并保存不可变批准决定；不要签发或消费真实发布证明。

## 通过条件

以下证据全部存在才通过：

- 任务绑定 exact SKU、原图资产和完整版本化配方；
- 候选字节可以读取，SHA-256 与任务输出一致；
- 至少一条不可变 `selected / rejected / rework_requested` 反馈；
- 如发生返工，新任务继承同一配方编号并递增配方版本和候选轮次；
- “作图配方表现”按该 exact SKU 显示候选数、采用/拒绝/返工、人工秒数、生产耗时和实际成本；
- Owner 批准绑定精确最终文件，不是只批准 Prompt；
- 全程没有图片 Provider 调用、费用预占或渠道发布。

该结果只能记为一次 Owner 真实制作闭环，不证明渠道接受、转化提升、经营收益或配方可重复有效。

## 立即停止

遇到下列任一情况停止并保留记录：SKU 不一致、原图权利不清、输出改变商品事实、哈希不一致、跨 Owner 数据、图片集合门禁异常、页面要求 Provider Key，或任何未经批准的外部写入。
