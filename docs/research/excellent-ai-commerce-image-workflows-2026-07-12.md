# 优秀 AI 电商作图工作流与采购验证

> 日期：2026-07-12
> 范围：外部成熟方案、真实工作流、案例与采购验证；不评价凌镜现有代码
> 证据说明：厂商客户案例均为 `quoted` 个案，不视为独立审计或普遍效果；没有公开原始数据的转化提升均不采信。

## 结论

对单人跨境卖家，当前最优秀的做法不是购买一个“万能 AI 作图模型”，而是按任务分层：

1. **主图合规层**：真实商品照片 → 自动去背景 → 确定性白底、尺寸、留白和格式模板。这一层最成熟，也最适合批量化。
2. **质感修整层**：在不改商品主体的前提下添加可控阴影、轻微补光、画布扩展。只做候选，逐图检查。
3. **营销创意层**：场景图、广告变体只用于副图或广告候选，必须与真实主图并存并做渠道内 A/B 测试。
4. **高风险层**：虚拟模特、新角度、穿戴效果、修改商品结构或文字，不进入第一版自动工作流。

推荐最小工具组合是：**渠道已有的免费/内置工具优先（Shopify Magic、Google Product Studio、Amazon Ads Image Generator）+ 一个电商专用去背景工具的按月试用 + 人工兜底**。目前没有证据支持凌镜先自建通用生成模型或多 Provider 平台。

## 外部优秀工作流

### 1. 去背景后人工兜底：最有现实证据

Vestiaire Collective 的公开客户案例描述了一条值得复制的采购路径：先签测试阶段，再进入 API 自动化；系统自动处理普通图片，含人体、衣架等复杂对象的图片转人工。厂商称其自动化了 80%–90% 的去背景，处理时间从数小时降到约一分钟，流程成本减半。[remove.bg 客户案例](https://www.remove.bg/ms/s/vestiaire-collective)

- `quoted`：上述比例、时间和成本来自供应商发布的具名客户案例。
- `inferred`：真正优秀的地方不是“全自动”，而是**自动处理简单样本、异常样本明确转人工**，并且先测试再签自动化合同。
- `unknown`：其样本构成、错误率、合同价和独立核算数据未公开，不能套用到凌镜。

另一个匿名大型零售商案例称，去背景从两天外包周转缩短到两分钟，每图成本下降 60%；该企业年处理约 300 万张图片，因此规模经济与单人卖家不同。[remove.bg B2C 案例](https://www.remove.bg/ja/s/b2c-ecommerce)

### 2. 渠道内编辑：最低摩擦的单人工作流

Shopify 官方编辑器已经把“主体检测 → 手工修正选区 → 纯色背景”与“提示词生成背景/灯光”分开。官方明确建议使用主体清晰、对比良好、边缘干净、构图简单的输入；生成结果默认约 1MP，一次生成一个场景，未保存候选可能在关闭编辑器后删除。[Shopify Media Generation 帮助](https://help.shopify.com/en/manual/shopify-admin/productivity-tools/shopify-magic/media-generation)

- `quoted`：去背景、纯色背景、生成背景和扩图均是 Shopify 当前提供的工作流。
- `inferred`：对 Shopify 卖家，先用内置编辑器验证，比先接第三方 API 更便宜且更贴近真实上架流程。
- `unknown`：官方没有公开不同商品类别的保真错误率，也没有证明生成图提高销量。

Google Product Studio 同样把去背景、提升分辨率和生成场景放在 Merchant Center 内。Google 称 80% 的受访使用者认为它提高效率，但样本仅为美国内部满意度调查 `n=149`；全球生成图中约三分之一被发布或下载。“发布或下载”不是销售效果。[Google Merchant Center 说明](https://blog.google/products-and-platforms/products/shopping/tips-for-new-merchant-center/)

### 3. 场景图直接进入广告测试，而不是替换事实主图

Amazon Ads 的工作流是：从商品详情选择商品 → 自动或按主题/提示词生成生活方式背景 → 生成多个广告素材 → 在广告控制台观察 CTR、ACOS 和 ROAS。官方把它定位在 Sponsored Brands、DSP、展示广告和 Brand Store 创意，而不是证明商品事实的主图。[Amazon Ads 使用指南](https://advertising.amazon.com/library/guides/how-to-use-ai-image-generators)

- `quoted`：Amazon 提供免费场景变体并建议用广告指标测试。
- `inferred`：这是当前最可靠的场景图价值验证方式，因为创意和指标处在同一广告系统；但仍需同时观察成交、退货和投诉，不能只看点击。
- `unknown`：Amazon 没有在该指南公开“AI 场景图相对真实摄影”的普遍增量。

Amazon 公布的工程流程也显示其方案以真实商品白底图为输入，生成背景，商品信息可从现有 listing 推断。[AWS 技术说明](https://aws.amazon.com/blogs/machine-learning/learn-how-amazon-ads-created-a-generative-ai-powered-image-generation-capability-using-amazon-sagemaker/)。这证明产品化路径存在，不证明所有输出都保持商品细节。

## 任务成熟度裁决

| 任务 | 当前成熟度 | 推荐用途 | 主要失败方式 |
|---|---|---|---|
| 去背景 | 较成熟 | 主图预处理、批量 SKU | 透明、毛发、反光、阴影、细线、人体/衣架误切 |
| 纯白底、尺寸、留白、格式 | 成熟且应确定性执行 | 渠道主图 | 规则配置错误、裁切过紧；不需要生成模型 |
| 人工可调阴影 | 中等 | 白底图质感候选 | 光向不一致、悬浮感、改变视觉尺寸 |
| 补光/清晰化 | 中等 | 低质量原图修整 | 伪造纹理、小字和边缘；不可替代重拍 |
| 扩图 | 中等 | 广告比例适配、非主体区域补齐 | 新增虚假物体、重复纹理、透视错误 |
| 生活方式场景 | 可用但实验性 | 副图、广告变体 | 比例、接触面、反射、使用场景和功效暗示错误 |
| 虚拟模特/试穿 | 类目专用、风险高 | 服饰探索，不进首版 | 版型、垂坠、尺寸、遮挡、人物一致性错误 |
| 从单图生成新角度 | 不成熟 | 不建议用于商品事实图 | 模型猜测不可见结构、接口、背面和配件 |
| 多步骤自然语言编辑 | 研究前沿 | 不采购为核心链路 | 指令组合时局部约束相互破坏 |
| 批量 SKU | 仅简单确定性任务成熟 | 去背景、模板化、缩放 | 错误被批量放大；生成背景跨 SKU 不一致 |
| A/B 图 | 测量方法成熟，不是作图能力 | 广告/流量足够时验证 | 样本不足、同时改价/广告/库存导致归因失败 |

2026 年公开的 EComEditBench 仍专门建立 1,000 个样本来评估添加、删除、移动、交换、替换及多操作组合，并使用区域标注和视觉模型裁判。[GMO-E2DIT 论文](https://arxiv.org/html/2607.00920v1)。`inferred`：多步骤局部编辑仍是研究问题，不能因演示成功就视为目录级稳定能力。

Google 的多服装虚拟试穿研究仍把身份保持、服装细节和布局控制列为模型要解决的核心问题。[M&M VTO 研究](https://research.google/pubs/mm-vto-multi-garment-virtual-try-on-and-editing/)。`inferred`：虚拟模特应使用专用服务、专门样本和服饰人员验收，不能用通用背景生成接口顺带完成。

## 单人跨境卖家的最小操作步骤

### A. 每个 SKU 的基础图

1. 自己拍摄或取得明确可处理的真实商品原图，保留原文件。
2. 先用渠道内置工具或电商专用工具去背景；手工修正选区。
3. 用确定性模板生成目标渠道需要的白底、画布、留白、分辨率和格式。
4. 对照实物/规格检查颜色、数量、结构、文字、标识、配件和包装。
5. 失败样本转人工，不反复让生成模型“猜对”。
6. 保存原图、输出图、工具、耗时、现金成本和拒绝原因。

### B. 只有需要广告创意时才做场景图

1. 从已经通过基础图检查的商品图出发。
2. 一次只变一个创意变量，例如背景场景；不同时改商品、文案和价格。
3. 生成 2–3 个候选，淘汰比例、接触、影子、反射或使用暗示不真实的图片。
4. 只放到副图或渠道广告实验，不替代真实主图。
5. 记录曝光、点击、花费、加购/成交、退款投诉；流量不足时结论保持 `unknown`。

## 20 张采购验证法

不要按首页演示采购。先建立 20 张属于自己未来货盘的盲测集：

- 5 张普通硬边商品；
- 3 张白色/浅色商品；
- 3 张透明或高反光商品；
- 3 张毛发、织物、网孔或细线边缘；
- 2 张包装含小字/商标；
- 2 张带自然阴影或接触面；
- 2 张复杂构图或低质量供应商图。

同一批图交给：现有确定性处理、候选 AI 工具、人工/外包基线。隐藏工具名称后逐张检查。

### 必记指标

| 指标 | 定义 |
|---|---|
| 首次通过率 | 无需返工即可用于指定渠道的张数 / 20 |
| 严重事实错误率 | 改变颜色、结构、数量、文字、配件或功效暗示的张数 / 20 |
| 人工修正时间 | 从上传到最终批准的 Owner 实际分钟数 |
| 最终采用成本 | 订阅/API/外包现金 + 失败重试成本，按最终采用图计算 |
| 异常可恢复性 | 失败能否保留原图、明确报错并转人工 |
| 批量一致性 | 同模板下主体比例、留白、背景色和阴影是否一致 |
| 数据与权利适配 | 是否允许上传该图、跨境处理、商业使用及删除 |

### 推荐通过线

以下是 `estimated` 的采购门槛，不是行业标准：

- 严重商品事实错误：0/20；
- 基础去背景首次通过率：至少 18/20；
- 相比人工基线，最终采用图的 Owner 时间减少至少 30%；
- 总现金成本不高于当前最佳替代方案；
- 所有失败均能转人工且不会覆盖原图；
- 通过后也只购买一个月或最小额度，不签长期合同。

若两个工具相近，优先选已嵌入实际销售渠道、支持人工修正和原图保留的那个，不按模型名或生成图数量选择。

## 效果验证边界

Google 曾报告，拥有多于一张图片的商品 offer 相比仅一张图有更多展示和点击（+76% impressions、+32% clicks），但这是 Google 全球内部观察，不是“AI 图片导致提升”，也没有在公开页面说明完整控制变量。[Google Product Studio 发布说明](https://blog.google/products-and-platforms/products/shopping/google-product-studio-generative-ai-product-photos/)

因此应分三层判断：

- **制作有效**：更快、更便宜地产出无事实错误、符合规则的图。
- **广告有效**：在同一商品、价格、受众、预算和时间窗口下，随机分流后指标改善。
- **经营有效**：扣除作图、广告、退款和售后成本后，最终经济结果改善。

一次点击率提升只支持“该创意在该流量样本中获得更多点击”，不证明利润提升，也不能外推到其他 SKU 或渠道。

## 对凌镜的采购建议

1. 先不接通用图片 API；用 20 张测试比较**渠道内置工具 + 一个电商专用去背景工具 + 人工基线**。
2. 如果只是白底主图，优先复用现有确定性处理，AI 只负责分割主体；不生成商品主体。
3. 如果确实需要场景广告，优先在 Amazon Ads、Google Merchant Center 或 Shopify 的实际渠道界面做 2–3 张小测试，避免先建设集成。
4. 只有重复使用后确认“跨渠道搬运、证据留存或批量处理”造成持续手工负担，才把胜出的单个工具接入凌镜。
5. 虚拟模特、新角度和多步骤编辑保持 `deferred`；等真实服饰 SKU 和专门验收需求出现后另做采购测试。

## 尚未知

- 当前 Owner 会使用哪个国家、渠道、类目和真实 SKU；
- 各工具对 Owner 自己货盘的真实通过率、费用和处理地域；
- 渠道内置工具在 Owner 账号及地区是否可用；
- 场景图是否能在足够流量下产生可重复的经济改善；
- 供应商图片是否具备上传第三方工具和商业改编的权利。

这些未知需要真实样本和账号验证，不应通过继续搜营销案例来填补。
