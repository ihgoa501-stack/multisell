# 凌镜 LingMirror 全量冲刺总计划

> 日期：2026-06-22
> 角色视角：项目负责人
> 目标：把当前“模块基本齐全的内测 MVP”推进到“可演示、可内测、可继续接真实业务”的准产品阶段。

## 1. 项目现状判断

凌镜当前不是原型，也不是从零建设阶段。它已经具备完整业务系统的主体骨架：

- 商品、SKU、品牌、类目、价格、库存、供应商已有基础闭环。
- 物流、平台费、决策、订单、结算、利润账本、异常工作台已有业务链路。
- Listing adapter、listing task、多平台发布队列已有技术骨架。
- Agent、AgentOS、Action Center、WorkItem 聚合、任务中心已有 AI AgentOS 雏形。
- 前端页面覆盖主要模块，当前前端构建可通过。

当前核心问题不是“没有东西”，而是：

- 链路还没有被压实成稳定演示路径。
- AgentOS 还没有完全成为业务中控入口。
- 真实平台、售后、批量运营、多仓、报表增强还没有完成产品化。
- 测试与依赖基线存在阻塞，后端当前被 `bcrypt 5.0.0` 与 `passlib 1.7.4` 兼容问题卡住。
- 文档状态落后于实际代码进度。

项目当前阶段判断：**70% 内测 MVP，进入全量冲刺收口阶段**。

目标阶段：**90% 准内测产品，核心链路可演示、可回归，剩余外部平台真实 API 进入集成验收**。

## 2. 冲刺原则

本轮不是做单点功能，而是一次性完善产品面：

- 不砍范围：P0/P1/P2 全部纳入总计划。
- 不平均用力：先打通主链路，再补强周边能力。
- 不做孤立功能：所有功能必须能回到 AgentOS、审计、异常、报表或业务闭环。
- 不追求一次上线生产：先达到稳定内测和可演示，再进入真实平台生产联调。
- 不做无边界重构：只修影响交付、测试、演示和后续扩展的问题。

## 3. 总体目标

本轮冲刺完成后，项目要达到：

- 老板/客户可以通过一条固定演示路径看懂系统价值。
- 运营人员可以在任务中心处理业务动作，而不是到处找页面。
- Agent 产生的建议可以进入 Action Center，经过审批、执行、复盘和审计。
- 订单、库存、物流、费用、利润、异常可以形成经营闭环。
- 批量改价、批量改库存、批量物流属性调整可以支撑日常运营。
- 售后退货、取消退库存、RMA 流程能补齐订单生命周期。
- 多仓分配可以支撑更真实的履约场景。
- 真实平台接入进入可联调状态，至少完成一个平台的真实 API 沙箱链路。
- 测试、构建、迁移、CI 检查具备基本准入门槛。

## 4. 全量战线

### 战线 A：工程基线与质量闸门

目标：让项目每天都能稳定跑、稳定测、稳定构建。

范围：

- 修复后端测试依赖阻塞：约束 `bcrypt<5` 或升级认证哈希方案。
- 恢复 AgentOS 相关后端测试。
- 保持前端 `npm run build` 通过。
- 建立最小 CI 检查：后端 focused pytest、前端 build、Alembic heads 检查。
- 清理文档与代码状态不一致的问题。

交付物：

- 后端测试可运行。
- 前端构建通过。
- CI 或本地准入命令明确写入文档。
- `docs/TIMELINE.md` 更新到真实进度。

验收标准：

- `cd backend && PYTHONPATH="$PWD" .venv/bin/python -m pytest tests/test_agentos_action_center.py tests/test_agentos_phase1.py -q` 通过。
- `cd frontend && npm run build` 通过。
- `cd backend && .venv/bin/alembic current --verbose` 可执行。

### 战线 B：AgentOS 总控闭环

目标：让 AgentOS 成为所有运营动作的统一入口。

范围：

- WorkItem 聚合继续作为统一任务模型。
- ActionProposal 完成创建、审批、拒绝、执行、复盘。
- 任务卡补齐执行、复盘、错误反馈、刷新状态。
- 操作日志可按 item、source、action 查询。
- Agent 详情页展示当前任务、历史操作、采纳率。
- 总控台展示待审批、严重风险、活跃 Agent、经营指标。

交付物：

- 任务中心可完成完整动作生命周期。
- Action Center 状态机稳定。
- WorkItem 与 ActionProposal 状态映射清晰。
- AgentOS 演示脚本可重复执行。

验收标准：

- 新建 `daily_report` 提案后可直接执行并复盘。
- 新建 `inventory_allocate` 高风险提案后必须先审批再执行。
- 拒绝提案后状态为 cancelled/rejected，不能再执行。
- 执行失败时显示后端错误，并保留 failed 状态。
- 每次操作都生成审计记录。

### 战线 C：真实平台接入

目标：从 mock adapter 推进到至少一个真实平台的可联调 API 链路。

范围：

- 梳理 `listing/adapters` 当前 mock/ozon/shopee/wildberries 结构。
- 选定首个平台优先级：Ozon 优先，其次 Shopee，再 Wildberries。
- 平台账号配置接入 `platform_integrations`。
- 完成真实 API 凭证保存、连接测试、类目/属性映射、草稿发布或商品发布。
- ListingTask 状态回写：queued、publishing、published、failed、blocked。
- 失败原因进入异常工作台和 AgentOS WorkItem。

交付物：

- 一个真实平台 adapter 进入沙箱/测试账号联调。
- ListingTask 可以通过真实 adapter 发起请求。
- 请求/响应日志可追踪。
- 发布失败可重试。

验收标准：

- 能配置平台账号并通过连接测试。
- 能读取或映射平台类目/属性。
- 能对测试商品发起真实发布请求。
- 成功/失败状态能回写 ListingTask。
- 失败能生成异常或 WorkItem。

### 战线 D：售后退货与订单生命周期

目标：补齐订单从支付到取消、退货、退款、库存回补的生命周期。

范围：

- `paid -> cancelled` 自动释放/回补库存。
- 新增或补齐 aftersales/RMA 模块。
- 支持退货申请、审核、收货、退款、关闭。
- 退款影响 FinanceLedgerEntry。
- 售后异常进入 ExceptionWorkbench。
- AgentOS 生成售后待办。

交付物：

- 售后退货 API。
- 售后前端页面或订单详情中的售后面板。
- 库存回补和利润账本调整。
- 售后审计日志。

验收标准：

- 已支付订单取消后库存正确回补。
- RMA 创建后可审核、完成、拒绝。
- 完成退货后财务账本生成退款/成本调整记录。
- 异常售后会进入 AgentOS 任务中心。

### 战线 E：Excel 批量运营

目标：把运营高频动作批量化，减少逐条维护。

范围：

- 批量改价。
- 批量改库存。
- 批量改物流属性。
- 导入预览。
- 错误行下载。
- 操作日志记录每批次摘要。
- 高风险批量动作进入 ActionProposal 审批。

交付物：

- `batch_ops` 后端模块。
- 前端批量运营页面。
- 模板下载、上传、预览、确认执行、结果下载。
- 与 AgentOS 审批联动。

验收标准：

- 上传 Excel 后能看到预览和错误。
- 无错误数据可确认执行。
- 执行后价格/库存/物流属性真实更新。
- 错误行可下载。
- 大批量或高风险改价必须审批。

### 战线 F：多仓库分配

目标：让库存从单 SKU 总量升级到多仓履约能力。

范围：

- 仓库管理。
- SKU 仓库库存。
- 分配规则。
- 自动分仓。
- 订单创建时按规则锁定对应仓库存。
- 多仓缺货异常进入 AgentOS。

交付物：

- 完善 allocation/inventory 交互。
- 前端多仓库存视图。
- 自动分配规则可配置。
- 订单履约可使用仓库库存。

验收标准：

- SKU 可查看各仓库存。
- 可手动/自动分配库存到仓。
- 订单锁库存时扣对应仓库。
- 仓库库存不足时明确失败并生成异常。

### 战线 G：报表增强

目标：从基础看板升级到经营分析面板。

范围：

- 订单报表。
- 库存报表。
- 发布成功率报表。
- 利润报表。
- 异常趋势。
- Agent 建议采纳率。
- 数据按日期、平台、SKU、仓库、Agent 过滤。

交付物：

- Dashboard 增强 API。
- 前端图表和筛选。
- AgentOS 总控指标接入真实数据。

验收标准：

- 可以看到今日/7日/30日销售、利润、订单、库存风险。
- 可以看到平台发布成功率。
- 可以看到 Agent 建议采纳率。
- 图表数据来自真实业务表，不是 mock。

### 战线 H：Agent 接真实数据

目标：让 Agent 不再停留在 mock 分析，而是基于业务数据提出建议。

范围：

- A1 选品看商品/供应商/利润数据。
- A2 Listing 看发布任务、平台规则、失败原因。
- A5 库存看库存、仓库、订单速度。
- A6 利润看费用、结算、账本。
- A7 合规看异常、平台字段、图片/文案。
- G1 总控看所有 WorkItem 和经营指标。

交付物：

- Agent 数据读取服务。
- Agent 建议自动生成 ActionProposal。
- 真实数据驱动的建议页面。

验收标准：

- 至少 3 个 Agent 能基于真实表产生建议。
- 建议能进入 Action Center。
- 建议能被审批、执行、复盘。
- 采纳率能回写 Agent 指标。

### 战线 I：权限与审计产品化

目标：让系统具备运营团队使用的权限边界。

范围：

- 前端按钮级权限隐藏/禁用。
- 后端所有 mutation endpoint 补齐 `require_permission`。
- 操作日志覆盖核心变更。
- AgentOS 操作日志进入统一审计。

交付物：

- 权限码与页面按钮映射。
- 前端权限指令或 helper。
- 审计查询页面增强。

验收标准：

- 无权限用户看不到或无法点击敏感按钮。
- 直接请求后端仍会被拒绝。
- 创建、修改、删除、审批、执行都有审计记录。

### 战线 J：搜索、导入、压测、CI

目标：补齐系统化工程能力。

范围：

- 全局搜索覆盖更多业务类型。
- 导入预览和错误下载组件抽象。
- 库存锁定、订单创建、批量改价压测。
- CI migration check。
- 基础 smoke test 脚本。

交付物：

- 搜索索引增强。
- 通用导入组件。
- 压测脚本。
- GitHub Actions 或等价 CI 配置。

验收标准：

- 搜索能查商品、SKU、订单、异常、任务、提案。
- 导入失败能定位错误行。
- 并发订单不超卖。
- CI 能阻止构建/迁移明显失败的代码进入主分支。

## 6. 时间规划

如果单人推进：

- 第 1 天：M1 + M2。
- 第 2-3 天：M3 售后和多仓主链路。
- 第 4-5 天：M4 批量运营。
- 第 6-8 天：M5 真实平台一个平台联调。
- 第 9-10 天：M6 权限、报表、搜索、CI、压测。

如果 3 人并行：

- 后端 1：工程基线、AgentOS、售后、多仓。
- 后端 2：真实平台、批量运营、报表、搜索。
- 前端/全栈：任务中心、批量页面、售后页面、多仓页面、报表、权限 UI。

并行情况下：

- 第 1 天：M1 + M2。
- 第 2 天：售后、多仓、批量运营基础完成。
- 第 3 天：报表、权限、搜索、真实平台联调基础完成。
- 第 4-5 天：集成、验收、压测、修复。

## 7. 验收总清单

### 产品验收

- 用户能从 AgentOS 看到当前经营风险。
- 用户能在任务中心处理 Agent 建议。
- 用户能完成审批、执行、复盘。
- 用户能批量维护价格、库存、物流属性。
- 用户能处理订单取消和退货。
- 用户能查看多仓库存和分配结果。
- 用户能看到利润、库存、发布成功率报表。
- 用户能看到操作审计。

### 技术验收

- 后端 focused tests 通过。
- 前端 build 通过。
- Alembic heads 可升级。
- 核心 mutation endpoint 有权限控制。
- 核心 mutation endpoint 有操作日志。
- 并发库存测试不超卖。
- CI 能跑基础检查。

### 演示验收

固定演示路径：

1. 打开 AgentOS 总控台。
2. 查看严重风险和待审批任务。
3. 进入任务中心。
4. 新建一个经营日报提案并执行。
5. 新建一个库存分配提案并审批执行。
6. 提交复盘。
7. 查看操作日志。
8. 创建订单并触发库存锁定。
9. 取消/售后并看到库存回补。
10. 批量改价并进入审批。
11. 查看利润和库存报表。
12. 发起一个平台发布任务并看到状态回写。

## 8. 决策

本项目冲刺不再按“单功能完成”衡量，而按“系统能力完成”衡量。

本轮核心交付定义为：

> 凌镜 LingMirror 成为一个能通过 AgentOS 统一驱动商品、库存、订单、平台发布、异常和经营动作的跨境电商 AI AgentOS。

所有 P0/P1/P2 都纳入计划。执行顺序按依赖和演示价值推进，不再把任何一块从总计划中移除。
