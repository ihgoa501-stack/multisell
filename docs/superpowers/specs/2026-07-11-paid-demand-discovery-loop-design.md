# 真实付费需求发现循环设计

> 日期：2026-07-11
>
> 状态：`superseded / historical / not executable`
>
> 权威边界：本文记录当时的付费需求发现设计，不是当前 Owner 授权；当前入口见 [海洋目标](../../OCEAN_GOAL.md)、[产品方向](../../PRODUCT.md) 和 [当前状态](../../CURRENT.md)。
>
> 目标：不预设平台、客户、类目或商品，通过 AI 对抗研究和受控真实实验，发现或证伪可核查的真实付费需求。

## 1. 一句话定义

凌镜首先不是选品软件，而是一套 **AI 付费需求验证循环**：AI 提出有来源的需求假设，另一组 AI 主动寻找反证，只有存活假设才进入 Owner 批准的小额真实实验，最后由订单、支付、物流、售后和结算事实裁决。

系统的工作不是证明 AI 是对的，而是尽快、低成本地发现 AI 错在哪里。

## 2. 成功定义

### 2.1 研究阶段成功

研究阶段成功不等于发现需求。它只表示系统产出至少一个满足下列条件的“可实验假设”：

- 需求表述具体到人群、场景、问题、规格方向和价格区间；
- 每项事实都有来源、时间、地区、指标定义和原始证据；
- 搜索、曝光、评论、榜单、竞品和宏观数据没有被写成付款事实；
- 最强替代解释已经被反证 Agent 主动攻击；
- 平台、收款、合规、物流、供应商和预算硬门可通过；
- 实验可在 Owner 批准的现金和不可回收损失上限内停止。

### 2.2 真实付费需求成立

本项目只有同时满足以下条件，才允许写“发现了真实付费需求”：

1. 至少 3 名互不关联的陌生买家；
2. 在至少 2 个不同自然日完成真实付款；
3. 订单对应同一个预先冻结的需求—规格假设；
4. 商品真实发出并签收；
5. 适用的取消、退货、退款、争议和拒付观察窗口结束；
6. 平台结算与订单级实际成本完整；
7. 扣除所有可归属变动成本后，实验最终贡献利润为正；
8. 没有亲友单、Owner 自买、供应商单、返现回购、测试单或不可剥离异常流量。

“3 名、2 天”是本项目首轮的最低重复性规则，不是统计学成功保证，也不是平台官方标准。它只用于避免把一个偶然订单冒充稳定需求。任何晚到退款、拒付或费用都会重开裁决。

## 3. 当前交付形态

第一版不建设大型新系统。采用三个最小组成部分：

1. **AI 研究流水线**：负责自动搜索、采集、翻译、归一和反证；
2. **证据账本**：保存假设、事实、来源、冲突、裁决和实验事件；
3. **Owner 决策卡**：只向 Owner 展示“我们知道什么、不知道什么、最强反证、下一步是否需要授权或花钱”。

连续两轮真实使用证明流程稳定后，才决定哪些部分值得做成长期软件模块。若文档、数据库视图或自动化脚本已经足够，就不为“看起来像产品”而建设新界面。

## 4. Agent 角色与边界

### 4.1 侦察 Agent

**职责**：从官方平台数据、公开市场页面、政府统计和已授权的一方经营数据中生成需求假设。

**允许**：只读搜索、采集、翻译、聚类、保存证据；提出待验证问题。

**禁止**：推荐采购；把热度写成付款；生成无来源销量、客户画像、费用、退货率或利润；为了凑数量重复颜色、店铺或同义词。

**输出**：`DemandHypothesis`，状态只能为 `lead`，不得自行升级为“需求成立”。

### 4.2 反证 Agent

**职责**：为每个假设寻找足以推翻它的解释和证据。

**必须攻击**：季节、新闻、促销、广告、品牌资产、地区差异、竞品交付优势、评论污染、搜索意图错配、合规门槛、物流、供应商质量、关联交易和成本遗漏。

**禁止**：为了显得谨慎而无限补材料；使用没有来源的风险故事；修改侦察 Agent 的原始证据。

**输出**：`FalsificationCase`，裁决为 `survives / evidence_missing / polluted / rejected`，并给出最强反证和下一项最低证据。

### 4.3 数据现实 Agent

**职责**：判断所需字段是否真的能从当前平台、账号、API、导出或公开页面取得。

**禁止**：把“代码里有适配器”写成“账号已连通”；用第三方平均值补平台权限、费用、销量或结算字段；绕过登录、验证码、权限和平台限制。

**输出**：`DataAccessDecision`，逐字段标记 `available / requires_owner_access / requires_listing / requires_transaction / unavailable / unknown`。

### 4.4 实验 Agent

**职责**：把一个存活假设转为最小、可停止、可归因的真实实验方案。

**允许**：准备规格、报价、预算、页面、操作草稿和单变量测试方案。

**禁止**：自行采购、发布、改价、开广告、发货、退款或补货；看到结果后修改主要终点、分母、观察窗或停止条件。

**输出**：`ExperimentProposal`。未获得 Owner 对每项外部写入和资金动作的批准时，状态保持 `draft`。

### 4.5 裁判 Agent

**职责**：只根据已经发生且可关联的事实升级或降级证据状态。

**禁止**：通过多数 Agent 投票裁决；用置信分代替付款、签收、售后和结算；把预计利润写成最终利润。

**输出**：`DemandVerdict`，状态只能来自固定状态机，并附一句 Owner 可读说明。

## 5. 证据状态机

```text
unfiled
→ lead
→ survives_falsification
→ experiment_ready
→ paid_provisional
→ delivered_provisional
→ retained_provisional
→ proven_positive_contribution
```

任何阶段均可转为：

- `evidence_missing`：关键证据暂时无法取得；
- `polluted`：关联方、激励、机器人或异常流量无法剥离；
- `rejected`：反证成立或硬门失败；
- `reopened`：晚到退款、争议、拒付、平台调账或成本改变旧裁决。

上游代理指标不能跨级。例如搜索量不能直接进入 `paid_provisional`，订单创建也不能直接进入 `delivered_provisional`。

## 6. 每轮循环

### 阶段 A：发现

侦察 Agent 从多个来源生成假设。每条假设必须写成：

> 在 `[国家/平台]`，`[可观察人群]` 在 `[场景]` 下可能愿意为解决 `[问题]` 支付 `[价格区间]`，候选解决方案需要满足 `[关键规格]`。

人群只能来自订单地区、平台市场、搜索/页面语义或其他可观察事实；不得编造年龄、收入、家庭结构或心理画像。

### 阶段 B：对抗

反证 Agent 独立工作，不接收侦察 Agent 的推荐结论，只接收原始主张和证据引用。它必须提出至少一个可执行反证测试。数据现实 Agent同时判断测试所需字段能否取得。

### 阶段 C：研究裁决

裁判 Agent按硬门处理：

- 反证成立：淘汰；
- 关键证据取不到：保持未知或停止；
- 有上游信号但无付款：只保留为假设；
- 反证后存活且实验可控：生成 Owner 决策卡。

### 阶段 D：Owner 审批

Owner 只需要回答具体问题，例如：

- 是否允许登录并读取某账号；
- 是否批准购买样品及金额；
- 是否批准发布一个明确 SKU；
- 是否批准广告日限额和总限额。

未批准不视为失败，实验保持等待状态。

### 阶段 E：真实实验

实验前冻结：假设、价格、目标地区、SKU、供应商/批次、流量来源、主要终点、排除规则、时间上限、曝光/订单上限、预算、不可回收损失、售后窗口和停止条件。每次只改变一个主要变量；若多个变量同时改变，只能裁决整个组合方案。

### 阶段 F：终局与下一轮

裁判 Agent按订单逐一连接：

`曝光 → 访问 → 加购 → 订单 → 付款 → 发货 → 签收 → 退货/争议 → 结算 → 实际贡献利润`

输出只能是：

- `停止`：硬门失败、证据污染、达到止损或最终贡献不为正；
- `换假设`：有流量但该问题/规格/价格没有获得可重复付款；
- `修正后再试`：证据指向一个可单独修正的变量；
- `小幅加码`：达到真实付费需求成立条件，且下一批仍在批准风险范围内。

## 7. 证据账本最小结构

每条事实至少保存：

```text
evidence_id
hypothesis_id / experiment_id
claim_type
source_system / source_url / official_field_name
raw_payload_or_snapshot
collected_at / timezone / covered_window
country / platform / region
currency / price_basis
evidence_level
fact_status: actual / quoted / estimated / unknown / conflict
collector / parser_version
related_order_or_transaction_id
falsification_status
```

每条假设至少保存：主张、可观察人群、问题、场景、规格、价格、支持证据、最强反证、未知项、当前状态、下一项最低证据和停止条件。

个人客户数据只保存完成关联所必需的去标识化键；不在研究报告中暴露姓名、地址、联系方式、支付资料或访问凭证。

## 8. Owner 决策卡

每次只展示六行：

1. **我们怀疑什么**；
2. **真实证据是什么**；
3. **这还不能证明什么**；
4. **最强反证是什么**；
5. **下一步需要多少钱或什么权限**；
6. **不做会怎样，停止线是什么**。

禁止在 Owner 界面展示 Agent 内部提示词、技术栈、模型争论或大段评分表，除非 Owner 主动要求。

## 9. 错误处理

- 来源无法读取：保存失败原因和时间，不用模型补值；切换到更高可信的官方导出/API，最后才请求 Owner 协助。
- 来源冲突：标记 `conflict`，默认采用较坏情景，不静默选择有利数字。
- 页面或字段定义变化：旧证据过期，重取并保留解析版本；影响裁决时自动重开。
- Agent 结论冲突：回到原始证据和状态机裁决，不按多数票。
- 平台登录、验证码或权限失败：停止自动化并请求窄范围授权，不绕过安全机制。
- 外部写入部分失败：记录每一步的外部 ID 和结果，停止后续资金动作，不伪装成成功。

## 10. 验证与测试

### 10.1 规则测试

- 搜索量、评论、榜单、竞品少、加购和订单创建不得升级为付款；
- 测试单、关联单、全额返现单必须进入 `polluted`；
- 未签收订单不得称有效成交；
- 售后窗口未结束不得进入 `retained_provisional`；
- 影响利润正负号的成本含 `estimated/unknown` 时不得输出最终正贡献；
- 晚到退款或平台调账必须把终局状态改为 `reopened`。

### 10.2 数据契约测试

对平台/API/导出保存固定样本，验证字段定义、币种、时间窗、订单—支付—物流—售后—结算关联和解析版本。任何 mock/fixture 只能验证程序，不能成为商业事实。

### 10.3 对抗验收

每个进入实验审议的假设必须有独立反证报告；反证 Agent 没有发现问题不等于通过，必须证明规定的反证清单已经执行。随机抽取证据，能够从 Owner 决策卡回到官方原始记录。

### 10.4 真实验收

最终验收只能使用真实账号、真实非关联买家、真实交易、真实物流、真实售后与真实结算记录。不能用测试环境、亲友订单、模拟数据、公开竞品订单或销售额替代。

## 11. 停止条件

### 停止某个假设

- 合规、收款、履约或平台硬门失败；
- 正常可售价格下无法形成正的保守单位贡献；
- 达到预注册时间、曝光、预算或损失上限仍无非关联付款；
- 三次独立重取同一关键事实仍冲突且无更高权威来源；
- 信号被证明来自关联方、机器人、激励或不可剥离污染。

### 停止继续桌面研究

当一个假设已经通过反证、具体 SKU/供应商/合规/物流/完整成本已连接，继续搜资料不再改变决策时，停止研究并提交 Owner 是否批准实验。研究不能无限延迟真实验证。

### 结束第一阶段

出现以下任一结果即可结束第一阶段并复盘：

- 一个假设达到 `proven_positive_contribution`；或
- 在预先批准的总实验次数、时间和损失范围内，所有假设均被证伪。

证伪所有假设也是有效结果，因为它避免继续投入错误方向；但它不代表永久不存在需求，只代表本轮证据和约束下没有可批准机会。

## 12. 已知边界

- Ozon、Shopee 和 Shopify 的卖家 API主要返回自有店铺已有 listing、订单和结算数据，不是全市场真实销量数据库；
- 没有具体报价展示给真实目标买家，AI只能提出有证据的假设，不能证明付费意愿；
- Shopify 可以测自店转化，但不会自动带来目标流量；
- 平台聚合分析、公开商品页和政府统计可缩小搜索范围，不能代替真实实验；
- 是否最终需要建设新软件，只能由两轮真实使用后的重复工作和错误成本决定。
