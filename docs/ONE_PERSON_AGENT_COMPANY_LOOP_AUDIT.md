# 一人 Agent 公司经营闭环审计

更新时间：2026-06-29
版本：v0.1 (Day 0)

---

## 审计目标

评估目前系统在实际经营场景下的能力现状。审计不仅看"功能有没有"，还要看"功能能不能串起来"。

### 演示场景

```
20 个候选商品
-> 资料完整度检查
-> 成本 / 物流 / 平台费 / 利润计算
-> Agent 给出上架建议
-> 生成任务 / 待审批
-> Owner 总控台看到风险、建议、审批、失败
-> 平台只读或模拟数据进入
-> 所有关键动作有记录
```

## 结果分类

| 分类 | 含义 |
|------|------|
| ✅ 已可用 | 现有代码直接支持，不需要或只需要少量接线 |
| ⚠️ 半可用 | 有部分能力，但需要新功能或显著增强才能跑通 |
| ❌ 不可用 | 不支持，需要新建 |

## 逐项审计

### 1. 候选商品数据

| 子项 | 状态 | 说明 |
|------|------|------|
| 产品基本 CRUD | ⚠️ 半可用 | ProductHub 有版本/关系/新鲜度，但没有独立的 candidate_product 表 |
| 采购成本录入 | ✅ 已可用 | supplier domain 有成本数据 |
| 包装/运输属性 | ❌ 不可用 | 需要新建到 candidate_product |
| 目标售价 | ❌ 不可用 | 需要新建字段 |
| 种子数据脚本 | ❌ 不可用 | 需要创建 seed 脚本 |

### 2. 资料完整度检查

| 子项 | 状态 | 说明 |
|------|------|------|
| 评分计算 | ❌ 不可用 | 需要新建 completeness domain |
| 缺失项清单 | ❌ 不可用 | 需要新建 |
| 检查 API | ❌ 不可用 | 需要新建 |
| 批量检查 | ❌ 不可用 | 需要新建 |

### 3. 成本 / 物流 / 平台费 / 利润

| 子项 | 状态 | 说明 |
|------|------|------|
| 采购成本 | ✅ 已可用 | supplier module，需要接线 |
| 物流运费 | ✅ 已可用 | logistics A10 费率引擎 |
| 平台费用 | ✅ 已可用 | platformfee module |
| 关税 | ✅ 已可用 | tariff module（新） |
| 利润汇总 API | ❌ 不可用 | 需要新建 profit_summary 接线 |

### 4. Agent 上架建议

| 子项 | 状态 | 说明 |
|------|------|------|
| Agent 注册 | ✅ 已可用 | A1-A11+G0-G3 |
| 决策点 | ✅ 已可用 | A8 (sourcing_recommend) 等 |
| 建议输出 | ⚠️ 半可用 | sourcing 有评估，但需要包装成 listing_recommendation |
| 建议原因（业务语言） | ❌ 不可用 | 需要 Agent 建议规则 |
| 建议存储到 decision | ✅ 已可用 | ProductHub 有 decision_record |

### 5. 任务生成 + 待审批

| 子项 | 状态 | 说明 |

| listingtask 模型 | ✅ 已可用 | 含 status/missing_requirements/decision_snapshot |

### 6. Owner 总控台

| 审批操作 | ❌ 不可用 | 需要新建 |
| 平台同步状态 | ❌ 不可用 | 需要新建 |

## 汇总

| 环节 | 状态 |
|------|------|
| 1. 候选商品 | ⚠️ 半可用 |
| 2. 完整度检查 | ❌ 不可用 |
| 3. 成本/利润计算 | ⚠️ 半可用 |
| 4. Agent 建议 | ⚠️ 半可用 |
| 5. 任务/审批 | ⚠️ 半可用 |
| 6. Owner 总控台 | ⚠️ 半可用 |
| 7. 平台数据 | ⚠️ 半可用 |
| 8. 审计记录 | ✅ 已可用 |

**结论：80% 的"零件"已存在，需要接线和增强才能跑通完整闭环。**

## 审计使用方式

- 每次 Day 完成后回审对应行
- 更新状态: ✅ → ⚠️ → ❌
- 记录是什么改动让状态变更
- 最终 Day 7 目标: 全部 ✅
