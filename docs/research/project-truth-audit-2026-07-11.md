# 凌镜项目真相审计

> 审计日期：2026-07-11
> 审计类型：只读、仓库级、多个独立 Agent 交叉核验
> 审计提交：`461a9a75b9e700fa06e433de2c9be3ee3872dbda`
> 状态：带日期的历史事实快照；证据边界可供核验参考，产品方向与行动顺序不是当前授权
> 方向限制：本文基于现已被 Owner 否定自动继承的 2026-07-11 自用经营提案；涉及“当前唯一主线”、预算、优先级和下一步的内容均为 `superseded / unconfirmed`
> 证据限制：未连接生产服务器、真实平台账号或生产数据库；因此不能证明真实市场、真实订单、真实结算或真实利润已经发生

## 1. 审计目的

本报告回答六个问题：什么是仓库可验证事实，什么是 mock、stub 或推断，什么已经工程完成，什么已经过期，当前经营主线是否堆齐，以及哪些误判会让 Owner 继续投入错误方向。

本报告不以代码量、页面数、测试数或多个 Agent 的一致意见提高经营事实等级。经营事实必须由真实来源、观察时间、业务对象、外部凭证和必要对账支持。

## 2. 声明等级

后续文档和交付报告应使用以下等级：

| 等级 | 含义 |
|---|---|
| `policy` | Owner 当前政策或约束，不代表已经实现 |
| `planned` | 计划建设，不能写成已完成 |
| `implemented` | 代码、迁移、路由或页面存在 |
| `automated_verified` | 自动测试或构建在注明环境和时间下通过 |
| `manually_verified` | 人工完成了注明步骤的真实操作验证 |
| `external_observed` | 已从外部平台或现实事件观察到，并保留来源和时间 |
| `reconciled` | 已与结算、银行、现金或其他可信凭证完成对账 |
| `mock` | 模拟、种子、演示或固定返回值 |
| `inferred` | AI 或人员推断，尚未由事实核验 |
| `superseded` | 已被新方向替代，仅供历史追溯 |

## 3. 总裁决

凌镜已经拥有规模较大的工程基础，以及经营实验后半段的部分可信实现；它尚未完成当前唯一主线，也没有仓库证据证明已经发现真实付费需求或跑出正的最终贡献利润。

| 范围 | 裁决 | 证据等级 |
|---|---|---|
| Go/Next 活跃技术栈 | 存在且可构建、可测试 | `automated_verified` |
| 实验案件、证据、闸门、对象关联 | 模型、迁移、API、页面和测试存在 | `implemented` / `automated_verified` |
| 最终利润与现金关联校验 | 后端已有同订单关联和对账门禁 | `implemented` / `automated_verified` |
| 候选市场比较与淘汰 | 未发现完整模型、API、页面和状态机 | `planned` |
| Owner 批准已选市场 | 未形成正式事实链 | `planned` |
| 独立 AI 反证 | 只有 `counter` 证据类型，不能证明 run 独立 | `planned` |
| 陌生非关联买家资格 | 未与订单主体形成确定性核验 | `planned` |
| 付款、签收、售后观察期 | 实验闸门未充分读取已有订单和售后事实 | `implemented` 但未闭环 |
| 真实市场、订单、结算、利润和现金 | 本次未取得外部或生产证据 | `unknown` |
| 外部平台生产可用 | 连接器代码存在，不代表账号、权限和线上契约可用 | `implemented`，生产状态 `unknown` |

## 4. 已经完成的工程事实

1. `internal/domain/experiment/` 已包含实验案件、证据、闸门和业务对象关联；`/api/v1/experiments` 已注册，前端 `/experiments` 调用真实 API。
2. 普通证据录入不能直接声明 `actual`；Owner 必须对来源和观察时间单独核验。
3. opportunity 阶段通过时要求支持证据和反证同时存在。
4. 最终利润闸门要求关联同一订单、结算和最终利润记录；结算必须来自受信来源并完成明细对账。
5. 现金回收与利润最终确认是两个独立状态，并要求银行或现金账户交易。
6. 本次审计运行结果：后端全量测试 116 个包、约 2900 个测试通过；前端 20 个测试文件、105 个测试通过；Next 构建通过。

这些结果证明测试环境中的工程行为，不证明真实经营事件发生。

## 5. Mock、stub 与误导性展示

1. 主侧栏存在硬编码的运行中任务、Shopee 补货、Ozon 价格比较、商品数和待处理数，不来自真实经营 API。
2. AI Orchestrator 在默认、缺实现、预算阻断或非生产故障路径下可回退到 deterministic stub；工具证据和推理仍含演示 SKU、广告指标和固定建议。
3. MoA 当前主要是模板化聚合，不是基于完整 Agent 输出的真实 LLM 综合。
4. 部分平台适配器会以空成功或 stub 返回，容易把“未实现”误判为“没有数据”。
5. 平台连接器存在，只能证明代码能力，不能证明对应市场成立、账号权限有效或生产写入安全。

## 6. 当前主线未堆齐的部分

### 6.1 市场选择前半段缺失

尚未形成完整的候选市场、市场对比、淘汰条件、数据预检和 Owner 选定市场事实链。当前实验案件可直接从 `opportunity` 开始，无法回答“为什么是这个国家、消费者、需求场景和渠道”。

### 6.2 中间经营事实没有确定性接线

订单模型已有付款和签收字段，售后模块也存在，但 experiment 的付款、履约和售后阶段主要依赖 Owner 核验的文本证据，没有充分读取：

- 买家是否非 Owner、非亲友、非供应商；
- 订单是否真实付款；
- 是否真实签收；
- 退货和争议观察期是否结束；
- 是否存在未决退款、拒付或退货。

### 6.3 最终决策存在 P0 漏口

当前 `continue` 条件要求利润状态 final 且现金已回收，但没有要求 `final_profit_amount > 0`。零利润或负利润案件可能满足继续条件，与当前经营定义冲突。现金金额和币种也没有与结算和利润完成充分一致性校验。

### 6.4 浏览器与生产验收不足

- 没有覆盖 experiments、候选市场、市场批准、最终利润和现金回收的核心 E2E；
- `npm run lint` 在本次审计中因 ESLint 10.7 与插件接口不兼容而失败；
- 镜像发布门没有强制依赖 E2E；
- 历史页面验证脚本使用过期端口和凭证，截图步骤只是占位；
- 本次未验证正式域名、真实登录、备份恢复、生产迁移和外部平台账号。

## 7. 已过期或冻结的方向

以下内容自 2026-07-11 起不得作为当前开发指令：

- 双产品架构、外部 SaaS、多租户、订阅计费和公共 API；
- 固定 Ozon、Shopee 或其他平台作为当前市场；
- 固定 `20→3→1`、`20→3–5` 等漏斗数量；
- 更多 Agent、MoA、自治升级和展示性仪表盘；
- 面向外部商品运营人员的上架生产闭环。

旧文档继续保留用于历史追溯，但必须标注 `superseded` 或 `frozen`，并指向 `docs/SELF_USE_OPERATING_DIRECTION.md`。

## 8. 当前最重要的行动顺序

1. 修复负利润也可能进入 `continue` 的终局逻辑。
2. 建立候选市场比较和 Owner 选定市场的最小事实模型。
3. 让付款、签收和售后闸门读取真实订单与售后对象，而不是只依赖文本证据。
4. 移除或明确标注前端硬编码经营状态，收缩 Owner 当前导航。
5. 为完整主线增加浏览器 E2E，再谈生产可用。

在这些工作完成前，不新增平台、Agent、MoA、仪表盘或大型视觉重构。

## 9. 复审触发条件

发生下列任一情况后应重新审计并生成新日期快照，不覆盖本文件：

- 候选市场或实验事实模型变化；
- 付款、签收、售后、利润或现金闸门变化；
- 首次取得真实平台账号和数据；
- 首次真实实验完成；
- 项目方向再次变化；
- 文档声称 Business Verified 或 Production Ready。
