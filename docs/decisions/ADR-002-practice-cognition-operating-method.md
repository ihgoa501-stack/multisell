# ADR-002：以“实践—认识—再实践—再认识”作为项目运行方法

## Status

Accepted

## Date

2026-07-13

## Context

ADR-001 已确定凌镜的唯一目的地：只供 Owner 本人使用的完整 AI 跨境电商经营平台。当前仓库已经积累大量领域代码、页面、测试和本地运行证据，但正式环境、真实渠道、真实供应商、真实发布、订单、结算、银行到账和最终利润仍有大量 `unknown`。

Owner 进一步明确：凌镜未来必须根据事实与结果持续调整，但真实经营目前受制于系统尚未完善。项目不能把“继续写代码”误认为已经完成经营实践，也不能要求一个尚不可安全运行的系统直接承担真实经营。

《实践论》中的“实践—认识—再实践—再认识”在凌镜中需要区分两类对象：

1. 对软件系统进行建设、测试和运行验收，形成对系统真实能力的工程认识；
2. 使用可安全运行的系统开展真实经营，形成对市场、商品、供应商、渠道、利润、方法和 Owner 判断的经营认识。

两类循环互相推动，但证据不能互相替代。

## Decision

凌镜采用以下项目运行方法：

```text
系统建设实践
→ 工程验证与运行验收
→ 认识系统实际能做什么、不能做什么
→ 修正并继续建设

相关经营路径达到安全可运行条件
→ 受控真实经营实践
→ 外部事实、结算、现金与最终结果
→ 形成不超过证据范围的经营认识
→ 调整经营行动和系统建设
→ 再次实践
```

### 1. 完整平台仍是目的地

本 ADR 不缩小或替代 ADR-001。市场与机会、商品与货源、渠道准备、交易经营、经营财务、经营决策、小Q协作和生产保障仍须完整建设。

### 2. “先完善系统”必须有可验收含义

完善不是无限增加功能。一个纵向流程只有同时完成必要模型、Owner体验、权限、审批、审计、错误处理、自动测试、真实环境运行、失败恢复和外部事实验收，才能称为该流程可用于真实经营。

尚未满足外部条件时，必须保持 `unknown`，不能以 mock、本地页面或自动测试冒充真实可用。

### 3. 不等待全部未来功能完成后才接触现实

完整平台不是一次性大爆炸交付。每条相关纵向流程在安全门槛完成后，应立即进行范围受控、可停止、可对账的真实运行验收；验收暴露的问题回到系统建设队列。后续单元继续建设，不能把第一条可运行流程误当成平台上限。

### 4. 明确两种实践和两种认识

| 实践 | 形成的认识 | 不得据此宣称 |
|---|---|---|
| 编码、测试、迁移、部署、恢复、模拟与隔离验收 | 系统在注明环境和条件下的能力与缺陷 | 市场成立、真实成交、真实利润或经营方法有效 |
| 真实研究、采购、发布、订单、履约、售后、结算与现金对账 | 对市场、商品、供应商、渠道和经营结果的有限认识 | 一次结果具有因果、可重复或规模化结论 |

### 5. 开发队列围绕真实可运行缺口排序

当前队列只优先接受以下工作：

- 补齐 ADR-001 全平台路径中尚不可运行的必要能力；
- 移除 mock、stub、假成功和不可信旁路；
- 接通真实来源、外部凭证、结算、银行和最终利润；
- 完成正式环境、监控、告警、备份、恢复、迁移、失败对账和操作手册；
- 让 Owner 能够理解、决定、操作并恢复完整经营流程；
- 让真实经营结果进入下一次 Owner 决定。

无法说明服务于哪一个真实可运行缺口的相邻功能，不进入当前队列。

### 6. 认识必须允许被实践推翻

系统、AI和Owner的判断必须保留当时依据、未知、反证和停止条件。后续结果只可形成 `support / counter / conflict / unknown` 等有限结论，不能改写当时事实或自动宣称因果。

### 7. 下一次行动必须真实发生

报告、复盘或AI建议不是“再实践”。只有新认识形成新的Owner决定，并再次进入受控系统建设或真实经营行动，循环才继续。

## Completion Gates

每条纵向流程依次使用以下门槛，不得跳级：

1. **设计成立**：对象、来源、职责、安全和失败语义明确；
2. **工程成立**：代码、迁移、页面和自动测试通过；
3. **运行成立**：隔离或正式环境的部署、权限、恢复和人工操作通过；
4. **外部事实成立**：真实平台或现实事件有来源、时间和外部凭证；
5. **经济结果成立**：涉及金额时完成结算、银行到账和最终利润对账；
6. **下一轮成立**：结果形成新决定并进入下一次行动。

某一门槛未满足时，只能报告实际达到的等级。

## Alternatives Considered

### 先建设一个独立数据或学习中心

拒绝作为当前优先事项。现有经营事实、经营决定、受控行动和小Q边界应优先复用；独立中心会复制事实，却不能自动解决真实运行和结果缺失。

### 先完成所有未来功能，再开始真实运行

拒绝。缺少真实环境反馈会让错误设计在全平台扩散，也无法定义“所有未来功能”的终点。

### 系统未完整时立即进行无保护的真实经营

拒绝。采购、发布、价格、退款和资金等外部行动必须先完成对应权限、审批、审计、幂等、失败对账和停止条件。

### 把代码测试或一次交易视为完整学习

拒绝。工程证据与经营证据必须分开；一次结果只能判断该次事实，不证明可重复性。

## Consequences

- ADR-001 继续决定平台目的地和范围；本 ADR 决定项目如何推进和认识结果。
- 当前执行入口改为 `docs/plan/REAL_OPERATION_READINESS_PLAN.md`。
- `AGENTS.md`、`CLAUDE.md` 和当前优先级必须要求每项工作映射到真实可运行缺口及对应门槛。
- 现有 `businessdecision`、`businessfeedback`、小Q和经营事实领域继续复用，不新增第三套万能循环系统。
- 首次真实外部验收、首次结算现金闭合和首次下一轮行动发生后，必须生成新的带日期事实审计。
