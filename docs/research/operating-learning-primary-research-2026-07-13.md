# 经营事实—决策—行动—结果循环学习：一手资料研究

> 日期：2026-07-13
> 范围：只研究成熟架构、概念边界与适用条件；不改变凌镜 Owner-only 方向，不授权开发。
> 来源限制：只使用标准、官方文档和原始论文。
> 结论等级：外部来源内容为 `quoted`；对凌镜的适用判断为 `inferred`；仓库现状沿用项目审计标注。

## 结论

凌镜当前需要优先建立的不是“会自行训练的模型”，而是**可追溯的经营经历与检索复盘机制**：保留当时事实、AI 建议、Owner 决定、实际执行、结果观察和后续判断，并让小Q在新问题中检索相似经历。

这可以产生实际学习价值，但应准确称为**记录/检索学习**或**经营经验复用**。只有算法依据连续反馈更新模型或策略参数，并改变之后的动作选择，才属于机器学习意义上的**在线学习**。在线学习还需要稳定目标、可比较的重复决策、明确奖励、探索机制和可靠评估；凌镜目前没有真实行动与结果样本，不满足启用条件。

因此，最稳妥的目标结构是：

```text
权威经营事实（各领域继续持有）
  → 冻结事实清单
  → AI构思/建议（inferred）
  → Owner不可变决定
  → exact action执行与外部回执
  → 同对象、固定窗口的结果事实
  → support / counter / conflict / unknown
  → 下一次建议（仍是inferred，仍需Owner决定）
```

## 1. “构思”应该是什么

`inferred`：构思不是事实、决定或学习结论，而是一份**待验证的行动主张**。建议至少冻结：

- 当前经营问题与 Owner 目标；
- 使用的事实对象、版本、来源、观察时间和哈希；
- 建议动作、目标对象、输入参数与风险边界；
- 预期结果、观察窗口、支持/反对/无法判断条件；
- 已知反证、关键 unknown 和停止条件。

W3C PROV-DM 将溯源拆为 entity、activity、agent，以及生成、使用、派生、归属和责任关系；其目的之一就是支持对数据质量、可靠性和可信度的判断。[W3C PROV-DM Recommendation](https://www.w3.org/TR/2013/REC-prov-dm-20130430/)

`inferred`：凌镜不需要把所有领域数据复制进新的中心库。一个经营案卷只需保存不可变引用、版本/哈希、动作与责任关系；订单、库存、结算、利润等仍由权威领域持有。这比全系统改造成 Event Sourcing 或通用知识图谱更小，也更符合现有领域边界。

## 2. 三种“学习”必须分开

### 2.1 记录学习

系统保存完整经历，使人和AI能够复盘“当时知道什么、决定什么、真正执行什么、后来发生什么”。模型权重不变化。

它首先解决的是审计、可信来源和责任归属，不等于智能模型变聪明。W3C PROV-DM 支持的正是这种来源与过程追踪。[W3C PROV-DM Recommendation](https://www.w3.org/TR/2013/REC-prov-dm-20130430/)

### 2.2 检索学习

系统在新问题出现时检索过去经历，把相关事实与结果作为上下文交给小Q。模型参数仍可完全不变；能力提升来自外部非参数记忆和更好的上下文。

RAG 原始论文明确区分模型参数中的 parametric memory 与外部检索的 non-parametric memory，并指出检索结果可以提供来源。该论文证明“外部记忆 + 检索生成”是一类独立机制，不应被误写成模型已经在线训练。[Lewis et al., 2020, RAG](https://arxiv.org/abs/2005.11401)

### 2.3 模型/策略在线学习

在线学习要求系统按顺序接收情境、选择动作、取得损失或奖励反馈，再更新后续预测或动作策略。上下文赌博机（contextual bandit）原始论文的定义就是：根据用户与候选内容的上下文连续选择动作，并依据点击反馈调整策略。[Li et al., 2010](https://arxiv.org/abs/1003.0146)

所以以下行为**不是**在线学习：

- 新增一条事实或复盘记录；
- 让小Q读到历史案卷；
- 汇总某动作的成功率；
- AI根据提示词临时改变建议。

只有训练数据、模型参数、策略参数或确定性决策规则被受控更新，并影响后续选择，才算模型/策略层面的更新。

## 3. 少量数据时应该做什么

Google 的官方机器学习工程指南建议：没有数据时可以先不用机器学习；先设计和实施指标，首个模型保持简单，并优先把数据管道做可信。[Google Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml/)

因此凌镜早期应：

1. 记录每次构思的完整上下文、目标、动作与观察窗口；
2. 用确定性规则计算差异，例如利润、现金回收天数、退款率与库存变化；
3. 由小Q检索相似案卷并解释差异，不自动形成规则；
4. 结论只记为 `support / counter / conflict / unknown`；
5. 等出现足够多的同类、可比较决策后，再评估统计模型。

单次或少量经历可以帮助复盘和发现问题，但不能估计稳定效果，也不能证明可重复性。`inferred`：此阶段的“系统变好”来自记忆质量、检索质量和 Owner 纠正，不来自训练。

## 4. 何时才值得考虑上下文赌博机或在线策略

上下文赌博机适合大量重复、动作集合明确、奖励能较快返回的决策；它会在利用已知较优动作和探索未知动作之间权衡。[Li et al., 2010](https://arxiv.org/abs/1003.0146)

离线评估也不是读取普通历史记录即可。Li 等人的 replay 方法依赖随机记录策略产生的日志；只有历史动作与待评估策略动作匹配时才使用相应反馈，从而避免直接拿有选择偏差的日志评价新策略。[Li et al., 2011, Unbiased Offline Evaluation](https://arxiv.org/abs/1003.5956)

`inferred`：凌镜至少满足以下条件后才应讨论在线策略：

- 同一种决策重复发生，且目标含义稳定；
- 动作空间、禁止动作与 Owner 风险上限已定义；
- 奖励公式和观察延迟已固定；
- 每次选择记录 context、action、policy/version、选择概率、reward 与延迟结果；
- 有安全探索预算、停止线、离线回放和回滚；
- 在线策略只能提议或在 Owner 预先批准的低风险范围运行。

采购、发布、价格、大额预算等外部写入不应仅因模型置信度高而自动探索。

## 5. 如何避免把相关性冒充因果

Pearl 的原始论文专门区分统计关联与因果影响，并以 intervention（干预）为核心表达；仅观察 `P(Y|X)` 不能自动得到 `P(Y|do(X))`。[Pearl, 1995](https://proceedings.mlr.press/r0/pearl95a.html)

Rubin 的潜在结果框架指出，应尽可能使用随机化；非随机观察资料要做因果估计，必须依赖更强的控制与假设。[Rubin, 1974](https://dash.harvard.edu/entities/publication/73120378-82c0-6bd4-e053-0100007fdf3b)

在线受控实验文献同样把随机分配的 Control/Treatment 视为判断改动效果的核心，并系统讨论样本污染、指标选择、机器人流量和实验运行等陷阱。[Kohavi et al., 2009](https://link.springer.com/article/10.1007/s10618-008-0114-1)

因此每次结果应分级：

| 情况 | 可写结论 | 不可写结论 |
|---|---|---|
| 动作后指标变化，无对照 | 与动作时间相关；`support/counter/conflict` | 动作导致结果 |
| 有历史对比但同期环境变化 | 条件性关联；列明混杂因素 | 稳定因果效果 |
| 随机或可信准实验，设计与数据质量通过 | 在定义人群、动作和窗口内估计效果 | 自动外推到其他人、渠道或时期 |
| 样本不足或结果延迟未结束 | `unknown` | “暂时没看到坏结果”即有效 |

必须保留至少这些混杂因素：时间、价格、广告、库存、渠道流量、履约、竞争变化、平台规则和 Owner 同期其他动作。无法可靠区分时就保持 `unknown`。

## 6. Owner 审批怎样永久保留

NIST AI RMF 将人机角色和监督职责作为治理要求，并强调文档可以增强人工审查和问责；执行负责人仍对 AI 风险决定负责。[NIST AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)

Microsoft 的人机交互原始研究提出：系统应明确能力边界、支持高效纠正，并谨慎地从用户行为学习，而不是把行为直接当作可靠偏好。[Amershi et al., 2019](https://doi.org/10.1145/3290605.3300233)

`inferred`：凌镜应保持以下不可跨越的分层：

```text
AI构思（可修改，inferred）
  ≠ Owner决定（不可变）
  ≠ 动作授权（绑定 exact target + input hash + capability）
  ≠ 执行回执（实际发生）
  ≠ 结果观察（事实）
  ≠ 学习结论（仍可能只是 inferred）
```

- Owner 只批准被冻结的 exact action；构思、输入、目标或风险边界变化后旧批准失效。
- 结果与复盘不能反向改写当时事实、建议或决定。
- 小Q可以保存新建议，不能根据“学到了”自行形成 Owner 决定。
- 即使未来启用在线策略，策略版本更新和可执行权限仍是两件事；更新后的策略默认只产生建议。
- 拒绝、不采取行动和 Owner 修正都应保存，但不能简单作为负奖励；它们可能反映风险偏好、时机或信息不足。

## 7. 多人差异问题

上下文赌博机论文说明，个性化依赖用户与候选动作的上下文，而不是一套对所有人相同的无条件规律。[Li et al., 2010](https://arxiv.org/abs/1003.0146)

`inferred`：如果未来真的出现不同经营者，必须把目标、资金约束、风险偏好、渠道权限和可行动作纳入上下文，并保证数据与策略隔离。某人的结果不能直接更新另一人的个人策略；跨人复用至少要经过授权、去标识、适用性判断和独立验证。

但当前方向仍是 Owner-only。现在不应实现租户模型、跨用户聚合或群体在线学习；只需避免把经验结论写成“对所有人普遍有效”。

## 8. 系统风险

Google 的原始工程论文指出，真实 ML 系统会产生隐藏反馈环、未声明消费者、数据依赖和外部世界变化等技术债；模型输出影响未来输入时尤其容易形成自我强化。[Sculley et al., 2015](https://papers.nips.cc/paper/5656-hidden-technical-debt-in-machine-learning-systems.pdf)

凌镜需要特别防止：

- 小Q建议某类商品更多，随后只观察到这类商品，误判为其天然更优；
- Owner批准行为被当作客观正确标签；
- 未执行或未曝光的动作没有结果，却被统计成失败；
- 结果窗口未结束就提前更新经验；
- 模型输出回流为事实来源；
- 策略升级后无法重放当时版本与输入。

## 9. 对凌镜的最小建议边界

`inferred`：研究支持的是在现有 `businessdecision`、`businessfeedback`、权威领域事实和小Q Capability 上补齐统一案卷与检索，不支持新建通用数据中心或立即训练模型。

第一阶段验收只需证明一类真实经营动作能够完整回答：

1. 当时依据了哪些可验证事实？
2. 小Q建议和 Owner 决定分别是什么？
3. 外部世界实际执行了什么？
4. 到约定时间观察到了什么？
5. 哪些结果支持、反对、冲突或仍未知？
6. 下一次建议能否引用该经历，但仍不越过 Owner？

只有真实重复数据证明检索复盘不足时，才进入模型训练评估；只有具备安全探索和可靠奖励时，才进入在线策略评估。
